# Template Extraction Experiment

## 목적

장문 자유문서를 읽고 반복 사용 가능한 템플릿 구조와 입력 필드 후보를 만들 수 있는지 실험한다.

대상 샘플:

- `demo-samples/sample-long-contract-review.txt`
- `demo-samples/sample-long-customer-inquiry.txt`
- `demo-samples/sample-long-internal-report.txt`

## 실험 방식

1. 문서에서 구조적 메타 정보, 연락처, 금액, 날짜 같은 규칙 기반 필드를 먼저 식별한다.
2. 계약유형, 내부 검토 포인트, 고객 불만, 후속 조치처럼 문맥형 필드는 별도 필드로 승격한다.
3. 문서 본문을 placeholder 기반 템플릿 텍스트로 변환한다.
4. 결과를 `template.json` 과 `template.txt` 로 각각 저장한다.

## 문서별 템플릿화 결과

### 1. 계약 검토 의뢰서

- 문서 유형: `contract_review_request`
- 잘 구조화되는 필드:
  - 의뢰일
  - 의뢰자/의뢰 조직
  - 상대방 회사명
  - 대표자
  - 주소
  - 사업자등록번호
  - 계약명
  - 계약유형
  - 총 계약금액
  - 분쟁해결조항
  - 내부 검토 포인트
- LLM 문맥 판단이 필요한 영역:
  - "법무팀 권고사항"을 내부 검토 포인트로 묶는 일
  - `termination 조항`, 책임 한계, 지재권 분배를 리스크 카테고리로 정리하는 일

### 2. 고객 문의 처리 로그

- 문서 유형: `customer_inquiry_log`
- 잘 구조화되는 필드:
  - 접수일시
  - 접수채널
  - 담당자
  - 고객사명
  - 고객 담당자
  - 고객 등급
  - 사업자등록번호
  - 월 비용 / 일할 계산 금액
  - 후속 마감일
- LLM 문맥 판단이 필요한 영역:
  - 문의 내용 요약
  - 처리 경과 타임라인 요약
  - 분쟁 가능성/보상 가능성 판단
  - 내부 비공개 논의 내용을 요약 필드로 축약하는 일

### 3. 주간 내부 보고서

- 문서 유형: `weekly_internal_report`
- 잘 구조화되는 필드:
  - 보고일
  - 보고자
  - 수신자
  - 예산/매출/비용/순이익
  - 신규 계약 금액
  - 지원 요청 예산
  - 담당자 연락처
- LLM 문맥 판단이 필요한 영역:
  - 주요 업무 현황 요약
  - 기술적 이슈 분류
  - 고객 피드백과 개선 계획 정리
  - 다음 주 추진 목표/지원 요청을 action item 형태로 묶는 일

## 규칙 기반으로 충분해 보이는 필드

- 회사명 후보
- 이메일
- 전화번호
- 금액
- 날짜
- 주소
- 사업자등록번호
- 법인형 접두어 포함 조직명

## LLM 문맥 판별이 필요한 필드

- 계약유형이 실제 계약 메타인지, 설명 문장 일부인지 구분
- 검토 필요 사항, 리스크 포인트, 내부 권고사항 묶기
- 고객 문의의 핵심 문제와 처리 경과의 의미 요약
- 내부 보고서에서 "성과", "이슈", "지원 요청" 구획 재구성
- 인물/조직 후보가 문서 안에서 어떤 역할인지 확정

## 템플릿 추출에서 어려운 점

- 같은 사람/회사 정보가 문서 여러 위치에 반복되며 역할이 달라질 수 있다.
- 장문 문서는 숫자와 금액이 많아도 모두 같은 중요도를 갖지 않는다.
- "내부 검토 의견", "비공개 논의 사항", "경쟁사 동향" 같은 블록은 규칙보다 문맥 해석이 중요하다.
- 리스트/문단/타임라인이 혼합된 문서는 섹션 경계를 안정적으로 잡는 기준이 필요하다.

## 규칙 기반 vs LLM 분리 관점

### 규칙 기반 선행 추출

- 값 후보를 빠르게 모은다.
- 민감정보 치환 엔진과도 재사용 가능하다.
- 주소, 이메일, 전화번호, 금액, 날짜는 우선 규칙 기반으로 충분하다.

### LLM 후행 정리

- 후보값에 역할 라벨을 붙인다.
- 문서 유형을 결정한다.
- 리스트를 더 상위의 템플릿 필드로 묶는다.
- 자유문장을 `internal_review_points`, `customer_issue_summary`, `follow_up_actions` 같은 구조 필드로 바꾼다.

## 결론

현재 샘플 3종 기준으로 보면, "자유문서를 규칙 기반 값 추출 + LLM 문맥 재구성" 방식으로 템플릿화하는 것은 충분히 실험 가치가 있다.  
특히 계약 검토서, 고객 문의 로그, 내부 보고서처럼 반복 포맷이 있는 문서는 템플릿 전환 가능성이 높다.
