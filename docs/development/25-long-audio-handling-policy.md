# 25. Long Audio Handling Policy

## 목적

이 문서는 현재 IPU manual-preview의 음성 입력에서 긴 음성을 어떻게 다뤄야 하는지 운영 기준을 고정한다.

## 왜 분리하는가

- 현재 로컬 Whisper 경로는 짧은 샘플 기준으로만 실측이 있다.
- `15초`, `30초` benchmark는 관찰값이 있지만, 품질과 속도가 안정적이라고 일반화할 단계는 아니다.
- 실제 품질 샘플은 짧은 한국어 발화에서도 흔들린다.

즉 현재 음성 입력은 "연결은 됨"과 "운영 기준이 섬"을 구분해서 다뤄야 한다.

## 현재 운영 기준

### 데모에 바로 써도 되는 범위

- `5초 ~ 15초` 짧은 단일 음성 샘플
- 단일 화자 위주의 간단한 발화
- 로컬 dev/demo 환경에서의 수동 시연
- "음성을 넣으면 전사 후 민감정보를 치환한다"는 흐름 설명

### 내부 검증 범위

- `30초 미만` 샘플
- 품질 편차를 감수한 비교/실험 용도
- 다만 속도와 품질을 운영 기준으로 약속하지는 않는다

### 기본 지원으로 말하면 안 되는 범위

- `1분 이상` 긴 음성
- 회의 녹음 전체본
- 다화자 분리
- 자막 수준 정확도
- timestamp / segment 정밀 활용
- 잡음이 큰 현장 녹음

## 현재 제품 메시지 기준

- 음성 업로드는 제품에 노출한다.
- 하지만 현재 강점은 "짧은 음성을 manual-preview 흐름에 연결한다"는 점이다.
- "긴 음성도 안정적으로 잘 받아쓴다"는 메시지는 현재 금지한다.

## 권장 처리 방식

### 사용자 안내

- 긴 음성은 업로드 전에 짧게 나눠서 넣도록 안내한다.
- 가능하면 `5초 ~ 15초`, 길어도 `30초 미만`으로 자른 샘플부터 검토한다.
- 회의 녹음 전체본은 현재 manual-preview 기본 경로로 권장하지 않는다.

### 운영 판단

- 데모 자료는 짧은 샘플 위주로 고정한다.
- 긴 음성은 별도 STT 품질 검토 없이는 공식 데모에 넣지 않는다.
- 다화자 / timestamp / 자막형 출력은 별도 확장 과제로 분리한다.

## 향후 확장 조건

아래가 확보되기 전까지는 긴 음성을 기본 지원으로 승격하지 않는다.

1. `1분`, `3분`, `5분` 구간 속도/메모리 baseline
2. 한국어 긴 발화 품질 샘플셋
3. 긴 음성 분할 전략
4. 다화자 / timestamp 정책 결정
5. long-audio 전용 검증선

## 현재 결론

현재 IPU의 음성 입력은 짧은 샘플 데모와 내부 검증에는 쓸 수 있다.  
반면 긴 음성은 아직 기본 지원이 아니라 "분할 후 사용 권장" 단계로 유지한다.

긴 음성 verification 기준은 [`28-long-audio-verification-policy.md`](./28-long-audio-verification-policy.md) 를 따른다.
