# 15. Logging And Audit Scope

## 목적

이 문서는 IPU AI Security Filter의 현재 로그와 감사 범위를 어디까지 허용할지 정리한다.  
핵심은 "운영 관찰은 하되, 원문과 민감정보는 남기지 않는다"는 원칙을 코드와 운영 기준으로 고정하는 것이다.

## 현재 결론

현재 `manual-preview` 계층은 아래 3개 이벤트만 남긴다.

- `manual_preview_started`
- `manual_preview_succeeded`
- `manual_preview_failed`

이 단계에서는 이것만으로 충분하다.  
추가 이벤트는 실제 운영 요구가 생길 때 늘리되, 먼저 원문 비노출 원칙을 지켜야 한다.

## 허용 로그 필드

현재 남겨도 되는 필드는 아래 메타 정보뿐이다.

- `request_type`
  - `text` 또는 `file`
- `policy`
- `content_type`
- `session_id`
- `detection_count`
- `replacement_count`
- `report_strategy`
- `processing_ms`
- `error_type`

이 필드들은 운영 상태 확인과 장애 진단에 필요한 최소 범위다.

## 금지 로그 필드

아래는 현재 단계에서 로그에 남기면 안 된다.

- 원문 전체 텍스트
- 치환 전 탐지 값
- 이메일 주소 원문
- 전화번호 원문
- 사람 이름 원문
- 조직명 원문
- 금액 원문
- 치환 후 텍스트 전문
- 복사용 프롬프트 전문
- 업로드 파일 본문

즉 "무슨 타입을 몇 개 처리했는지"까지만 남기고, 실제 내용은 남기지 않는다.

## 감사 로그와 애플리케이션 로그의 구분

현재는 엄격한 의미의 별도 감사 로그 시스템이 없다.  
지금 남기는 것은 `운영 메타 로그`에 가깝다.

구분은 이렇게 둔다.

### 현재 운영 메타 로그

- 서비스 정상 동작 여부 확인
- 성능 측정
- 실패 유형 분류
- 정책/입력 타입 사용 현황 확인

### 미래 감사 로그

- 누가 요청했는지
- 어떤 문서 유형을 처리했는지
- 어떤 정책으로 처리했는지
- 결과를 저장했는지
- 언제 삭제했는지

즉 현재는 "요청 행위"보다 "시스템 상태" 쪽에 초점을 둔다.

## 로그 보관 원칙

현재 단계 권장 기준:

- 개발/데모 로그는 짧게 보관
- 운영 로그도 민감정보 전문은 저장하지 않음
- 세션 저장소 TTL과 로그 보관 기간은 분리해서 생각

중요한 점:

- session store TTL 은 `restore` 가능 시간이다
- log retention 은 운영 관찰 기간이다
- 둘은 같은 값으로 묶지 않는다

## 파일 업로드 관련 원칙

파일 업로드에서도 아래만 남긴다.

- `request_type=file`
- `content_type`
- `policy`
- `session_id`
- 탐지 수 / 치환 수 / 처리 시간 / 실패 타입

남기지 않는 것:

- 파일명 원문
- 파일 본문
- 추출된 텍스트 전문

파일명도 민감정보를 포함할 수 있으므로 현재는 로그에 넣지 않는 편이 맞다.

## 실패 로그 원칙

실패는 두 갈래로 나눈다.

### 사용자/입력 오류

예:

- 지원하지 않는 확장자
- 비어 있는 파일
- 암호화 PDF
- `.hwp` 변환 안내
- OCR 도구 미설치

이 경우:

- `warning` 수준 메타 로그만 남긴다
- stack trace 전체는 남기지 않는다

### 시스템 오류

예:

- 예기치 않은 exception
- DB 접근 오류
- parser 내부 버그

이 경우:

- `exception` 로그를 남긴다
- 그래도 원문과 민감정보 본문은 남기지 않는다

## 현재 재시작 지점

다음에 로그/감사 체계를 확장할 때는 아래 순서로 가는 것이 맞다.

1. 사용자 식별 필드 추가 여부 결정
2. 감사 이벤트와 운영 메타 로그 분리
3. 로그 보관 기간과 삭제 정책 문서화
4. 필요하면 JSON structured logging 으로 전환

## 지금 하지 않는 것

- 요청 본문 샘플 저장
- 디버그를 위한 원문 캡처
- 파일 전문 샘플 보관
- 프롬프트 전문 저장
- 사용자별 활동 추적

이건 상용 운영 요구가 생겨도 별도 동의와 정책 설계 없이 열지 않는다.
