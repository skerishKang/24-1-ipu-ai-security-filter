# 42. Demo Scenario - Text Input Flow

## 목적

이 문서는 IPU manual-preview의 **시연용 핵심 플로우**를 고정한다.  
"바로 시연 가능한 보안 제품 데모"를 위한 최소한의 시나리오다.

## 시연 플로우 선택

### 선택 근거

40-reentry-intent-and-next-plan.md 기준:

1. **텍스트 붙여넣기 → 민감정보 치환 → 복용 프롬프트 확인** (1순위)
2. 문서 업로드 → 치환 → restore 확인
3. 음성 업로드 → STT → 치환 확인

**선택 이유**: 텍스트 입력은 가장 안정적이고, 데모 중 중단 가능성이 낮음

## Demo Scenario: 텍스트 입력 기반 보안 치환

### 시연 전 준비

1. 브라우저에서 `http://localhost:4241` 열기
2. backend가 `http://localhost:8241`에서 실행 중인지 확인

### Step 1: 원문 입력 (10초)

```
안녕하세요. 저는 삼성전자 솔루션사업본부의 김철수 대표입니다.
연락처는 02-1234-5678 이고, 이메일은 kim.cheolsu@samsung.com 입니다.
이번 계약 금액은 5억이며, 다음 주 화요일까지 확인해 주세요.
```

**작업**: 텍스트 영역에 위 내용 붙여넣기

### Step 2: Policy 선택 (5초)

- `default` 선택 (기본)
- 또는 `strict_token` 선택 후 비교

### Step 3: 치환 미리보기 생성 (5초)

- "치환 미리보기 생성" 버튼 클릭
- 로딩 상태 확인

### Step 4: 결과 확인 (30초)

화면 4개 영역 확인:

| 영역 | 보여줄 내용 |
|------|------------|
| 원문 | 입력한 원문 전체 |
| 치환본 | `__PERSON_0__`, `__PHONE_0__`, `__EMAIL_0__`, `__AMOUNT_0__` |
| 탐지 리포트 | EMAIL 1건, PHONE 1건, PERSON 1건, AMOUNT 1건 |
| 복사 프롬프트 | 외부 AI에 복사 가능한 포맷 |

### Step 5: 복사 후 설명 (20초)

- 복사 버튼으로 치환본 복사
- "이제 이 텍스트를 ChatGPT나 Claude에 넣어도 안전합니다" 설명
- 원문 유출 없이 민감정보가 보호됨을 강조

## 데모용 샘플 텍스트

### 샘플 1: 계약서 검토 (기본)

```
김현수 변호사 (02-5555-1234, lawyer@lawfirm.co.kr)님께,
삼성전자와 체결한 다음 계약건에 대해 검토 요청드립니다.
계약 금액: 15억원
결제 기한: 2024년 3월 31일
```

### 샘플 2: 고객 문의 (보수적)

```
고객명: 이영희
연락처: 010-9876-5432
이메일: younghee.lee@customer.net
문의 내용: 제품 A 관련하여 3천만원어치 주문 요청
```

## 데모 중 발생할 수 있는 질문과 답변

| 질문 | 답변 |
|------|------|
| 원문은 어디에 저장되나요? | 세션 단위로 메모리에만 유지되며, TTL(기본 15분) 후 자동 삭제됩니다. |
| 복원할 수 있나요? | 세션 ID가 유효한 동안 복원 가능합니다. (세션 히스토리 API로 조회 가능) |
| 어떤 정보가 보호되나요? | EMAIL, PHONE, PERSON, ORG(조직명), AMOUNT(금액) 등입니다. |
| policy 차이는? | default는 읽기 쉬운 별칭, strict_token은 더 보수적인 토큰 방식입니다. |
| 외부 AI에 실제로 붙여넣어도 되나요? | 네, 치환된 텍스트를 복사해서 외부 AI에 넣으시면 됩니다. |
