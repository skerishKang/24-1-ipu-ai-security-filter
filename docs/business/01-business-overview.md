# IPU AI 보안필터 사업 개요

## 1. 서비스 정의

IPU AI 보안필터는 기업과 공공기관이 민감한 내부 데이터를 외부 생성형 AI에 직접 노출하지 않고도, GPT, Claude, Gemini 같은 고성능 SOTA 모델을 안전하게 활용할 수 있도록 돕는 AI 보안 서비스다.

핵심 원리는 단순하다.

1. 사용자가 텍스트, 문서, 음성 데이터를 입력한다.
2. 내부 보안 엔진이 민감정보를 탐지한다.
3. 민감정보를 세션 단위로 문맥 유지형 치환 형태로 변환한다.
4. 외부 AI에는 변환된 안전한 데이터만 전달한다.
5. 응답은 내부에서 다시 복원하여 사용자에게 보여준다.

즉, "외부 AI를 막는 방식"이 아니라 "외부 AI를 안전하게 쓰게 해주는 방식"이다.

## 2. 왜 필요한가

현재 많은 대기업, 금융기관, 공공기관은 생성형 AI를 쓰고 싶지만 다음 문제 때문에 실제 활용을 제한하고 있다.

- 사내 기밀, 고객 정보, 계약 정보, 재무 정보 유출 우려
- 외부 LLM 사용 시 보안 부서 승인 어려움
- 로컬 LLM 구축 시 높은 GPU 인프라 비용
- 로컬 모델 사용 시 성능 저하와 운영 부담

결과적으로 조직은 두 가지 비효율 중 하나를 선택한다.

- 성능 좋은 외부 AI를 포기한다.
- 비싼 인프라를 투자해 상대적으로 성능이 낮은 로컬 모델을 운영한다.

IPU AI 보안필터는 이 딜레마를 풀기 위한 절충안이 아니라, 새로운 기본 인프라를 목표로 한다.

## 3. 고객이 얻는 가치

### 3-1. 보안

- 민감정보의 직접 외부 전송을 줄인다.
- 세션 기반 휘발성 매핑으로 원문 노출 위험을 낮춘다.
- 로컬 또는 사내 서버에서 보호 계층을 통제할 수 있다.

### 3-2. 성능

- 외부 최고 수준의 SOTA 모델을 그대로 활용할 수 있다.
- 로컬 LLM 성능 한계를 우회할 수 있다.
- 조직은 "보안 때문에 성능을 포기"하지 않아도 된다.

### 3-3. 비용

- 대규모 GPU 서버 투자를 줄일 수 있다.
- 고비용 로컬 추론 인프라 대신 경량 보안 엔진 중심 구조로 갈 수 있다.
- 사내 전면 로컬 LLM 도입보다 총소유비용을 낮출 가능성이 높다.

## 4. 제품 포지션

IPU AI 보안필터는 단순한 마스킹 툴이 아니다.

또한 일반적인 챗봇 UI도 아니고, 로컬 LLM 판매 제품도 아니다.

이 서비스의 포지션은 다음과 같다.

> 외부 SOTA AI를 기업 보안 정책 안에서 사용 가능하게 만드는 AI 보안 필터 계층

즉, 제품 카테고리로 보면 다음에 가깝다.

- AI 보안 미들웨어
- LLM 전처리/후처리 인프라
- 기업용 AI 보안 필터
- AI 사용 허용을 위한 보안 게이트 계층

## 5. 초기 제품 방향

초기에는 완전 자동형보다 반자동형이 더 현실적이다.

### 초기 MVP

- 사용자가 입력 데이터를 업로드한다.
- 보안 엔진이 변환본을 생성한다.
- 사용자는 변환본을 검토한다.
- 필요 시 사용자가 외부 AI에 직접 붙여넣는다.

이 구조는 치환 품질과 안정성을 먼저 검증하는 데 유리하다.

### 이후 확장

- 외부 AI API 자동 연동
- 응답 자동 역복원
- 정책 기반 차단/허용
- 사용자/부서별 보안 규칙
- 관리자 콘솔

## 6. 현재 권장 시장 진입 방식

초기 타깃은 일반 소비자 시장이 아니라 B2B와 B2G다.

우선순위는 다음과 같다.

1. 법무, 회계, 특허, 컨설팅 조직
2. 금융, 보험, 대기업 전략/재무/영업 조직
3. 공공기관과 공기업

이 조직들은 다음 공통점을 가진다.

- 문서 민감도가 높다.
- 생성형 AI 수요가 높다.
- 보안 승인 장벽이 높다.
- 비용보다 통제 가능성과 리스크 감소가 중요하다.

## 7. 한 줄 정리

IPU AI 보안필터는 민감정보를 내부에서 보호·변환한 뒤, 외부 SOTA AI를 안전하게 활용할 수 있게 해주는 기업용 AI 보안 서비스다.
