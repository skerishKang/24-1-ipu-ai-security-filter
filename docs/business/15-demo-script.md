# IPU AI 보안필터 Demo Script

## 목적

이 문서는 `IPU AI 보안필터`를 고객 미팅, PoC 제안 미팅, 내부 검토 자리에서 실제로 어떻게 시연할지 정리한다.  
핵심은 기술을 많이 설명하는 것이 아니라, 고객이 느끼는 문제와 해결되는 장면을 짧고 명확하게 보여주는 것이다.

## 데모의 기본 원칙

- 기능 나열보다 문제 해결 흐름을 보여준다.
- 고객이 이미 겪고 있는 상황에서 출발한다.
- 민감정보가 포함된 문서가 외부 AI로 직접 나가면 안 된다는 점을 먼저 상기시킨다.
- IPU를 거치면 같은 작업을 더 안전하게 할 수 있다는 것을 보여준다.
- 데모는 짧아야 한다. 5~10분 안에 핵심이 전달되어야 한다.

## 권장 데모 시간

- 짧은 소개형: 5분
- 표준 고객 미팅형: 7~10분
- 상세 설명형: 10~15분

## 데모 준비물

- 텍스트 입력이 가능한 프론트엔드 워크벤치
- backend manual-preview API
- 민감정보가 섞인 예시 문서 2~3개
- 치환 결과와 복사용 프롬프트가 보이는 화면
- 필요하면 고객 산업군별 예시 문구

## 데모 시나리오 개요

### 시나리오 1: 대기업 내부 문서 요약

예시 상황:

- 담당자가 외부 AI로 회의 메모를 요약하고 싶다.
- 하지만 문서 안에 회사명, 담당자 이름, 연락처, 금액 정보가 섞여 있다.

보여줄 포인트:

- 원문에는 민감정보가 그대로 있다.
- IPU를 거치면 민감정보가 내부에서 치환된다.
- 외부 AI에는 치환된 텍스트만 넘길 수 있다.
- 사용자는 원래 업무 흐름을 크게 바꾸지 않고 AI를 활용할 수 있다.

### 시나리오 2: 법무/구매 문서 검토

예시 상황:

- 계약 초안을 외부 AI로 검토하고 싶지만 거래처명, 담당자명, 계약 금액 때문에 직접 넣기 어렵다.

보여줄 포인트:

- 단순 마스킹이 아니라, AI가 읽을 수 있는 형태로 정리된 안전한 입력을 만든다.
- 복사용 프롬프트가 바로 생성되어 실제 활용 흐름이 보인다.

### 시나리오 3: 공공/금융 문서 기반 질의

예시 상황:

- 내부 보고서나 민원 대응 문서를 AI로 정리하고 싶지만 외부 반출이 어렵다.

보여줄 포인트:

- 보안 때문에 AI를 포기하지 않아도 되는 중간 해법이라는 점
- 로컬 LLM만 고집하지 않고도 통제 가능한 활용 모델을 만들 수 있다는 점

## 표준 데모 진행 순서

### 1. 문제 제기

말할 문장 예시:

`지금 많은 조직이 챗GPT나 클로드 같은 모델을 쓰고 싶어 하지만, 회사명, 인명, 연락처, 금액 정보가 들어간 문서를 그대로 넣을 수 없어서 실제 업무에선 제약이 큽니다.`

### 2. 원문 제시

원문 예시:

`아이피유테크 홍길동 이사는 고객사 contact@ipu.co.kr 과 010-1234-5678 정보를 포함한 제안서를 검토해 주세요. 계약 금액은 12,500,000원입니다.`

보여줄 포인트:

- 실제 업무에 가까운 텍스트
- 민감정보가 여러 종류로 섞여 있음

### 3. IPU 처리 실행

말할 문장 예시:

`이 문서를 바로 외부 AI에 보내는 대신, 먼저 IPU가 내부에서 민감정보를 탐지하고 치환합니다.`

화면에서 보여줄 것:

- 원문 입력
- 치환 결과
- 탐지 리포트
- 복사용 프롬프트

### 4. 치환 결과 설명

말할 문장 예시:

`여기서는 이메일, 전화번호, 인명, 금액 정보가 세션 기반 토큰으로 치환됩니다. 외부 AI는 이 치환된 정보만 보고 문맥을 분석하게 됩니다.`

보여줄 포인트:

- 민감정보가 그대로 노출되지 않음
- 어떤 정보가 탐지됐는지 리포트로 확인 가능

### 5. 활용 흐름 연결

말할 문장 예시:

`이 복사용 프롬프트를 외부 AI에 넣으면, 민감정보를 직접 넘기지 않고도 요약이나 분석을 수행할 수 있습니다. 초기에는 수동 모드로 쓰고, 이후에는 자동 연동으로 확장할 수 있습니다.`

### 6. 사업적 의미 정리

말할 문장 예시:

`중요한 점은 외부 AI를 막는 것이 아니라, 보안팀이 통제 가능한 방식으로 허용하는 계층을 제공한다는 점입니다. 그래서 로컬 LLM 구축에만 의존하지 않아도 됩니다.`

## 산업군별 멘트 조정

### 대기업

- 직원들이 이미 외부 AI를 쓰고 있을 가능성이 높다.
- 핵심은 `막는 것`보다 `통제 가능한 사용`이다.

### 금융권

- 보안 통제, 감사 대응, 승인 구조를 강조한다.
- `외부 AI 사용 허용을 위한 통제 계층`으로 설명한다.

### 공공기관

- 전면 도입보다 시범 도입과 제한된 범위를 강조한다.
- 안전한 사용 조건과 단계적 검증 구조를 보여준다.

## 데모에서 피해야 할 설명

- `완벽한 암호화`라고 과장하지 않는다.
- `100% 완전한 보안`이라고 말하지 않는다.
- 처음부터 자동 모드, 파일, 음성, 관리자 콘솔까지 다 보여주려 하지 않는다.
- 기술 깊이만 길게 설명하지 않는다.

## 데모 성공 기준

- 고객이 문제를 자기 일처럼 받아들인다.
- 고객이 `이건 우리 조직에도 필요할 수 있겠다`고 느낀다.
- PoC 범위를 상상할 수 있다.
- 단순 마스킹보다 현실적이라는 인상을 준다.

## 데모 후 이어질 질문

- 어떤 종류의 민감정보를 탐지할 수 있는가
- 치환 후 AI 품질이 얼마나 유지되는가
- 온프레미스가 가능한가
- 감사 로그나 정책 통제가 가능한가
- 우리 조직의 특정 문서에도 적용 가능한가

## 결론

좋은 데모는 기술 자랑이 아니라 `이제 외부 AI를 더 안전하게 쓸 수 있겠다`는 감각을 고객에게 주는 것이다.  
IPU AI 보안필터의 데모는 짧고 명확해야 하며, 수동 모드만으로도 충분히 문제와 해법을 설득할 수 있어야 한다.
