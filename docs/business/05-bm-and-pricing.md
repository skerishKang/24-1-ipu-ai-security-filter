# IPU AI 보안필터 BM 및 가격 정책 초안

## 1. 문서 목적

이 문서는 `IPU AI 보안필터`의 초기 비즈니스 모델과 가격 정책 방향을 정리하기 위한 초안이다.

현재 단계에서는 확정 가격표를 만드는 것이 아니라, 어떤 방식으로 돈을 받을지와 어떤 고객에게 어떤 모델이 맞는지를 구분하는 것이 목적이다.

## 2. 기본 BM 원칙

IPU AI 보안필터는 일반 소비자용 구독 서비스보다 기업용 B2B, B2G 중심이 적합하다.

따라서 가격 정책도 다음 기준을 따른다.

- 사용자 수보다 조직 단위 도입이 중요하다.
- 단순 API 사용량보다 보안 통제 가치가 더 크다.
- 고객은 "AI 모델 성능"보다 "보안 승인 가능성"에 비용을 지불한다.
- 초기에는 SaaS 단일 모델보다 PoC, 구축형, 연간 라이선스형을 같이 검토해야 한다.

## 3. 가능한 수익 모델

## 3-1. PoC / 파일럿 모델

가장 현실적인 초기 진입 방식이다.

### 형태

- 2주 ~ 8주 단위 유상 PoC
- 특정 부서, 특정 문서 유형, 특정 사용 시나리오로 한정
- 기능 범위와 보안 범위를 제한해 검증

### 장점

- 초기 고객 진입장벽이 낮다.
- 고객사 내부 승인용 명분이 생긴다.
- 실제 피드백을 제품 설계에 반영할 수 있다.

### 단점

- 반복 매출이 아니다.
- PoC만 많고 본계약 전환이 안 되면 비효율적이다.

### 권장 사용 시점

- 첫 고객 확보 단계
- 공공기관 시범사업 제안 단계
- 금융/대기업 내부 검토 단계

## 3-2. 연간 라이선스 모델

엔터프라이즈 소프트웨어에 가장 가까운 모델이다.

### 형태

- 조직 또는 부서 단위 연간 사용 계약
- 사용자 수, 부서 수, 정책 수, 처리량 등에 따라 가격 차등

### 장점

- 반복 매출 구조를 만들기 쉽다.
- 고객이 예산 편성을 하기 좋다.
- 유지보수와 정책 운영을 함께 묶을 수 있다.

### 단점

- 초기에 제품 신뢰가 충분하지 않으면 판매가 어렵다.
- 도입 시 내부 보안 검토 시간이 길다.

### 권장 사용 시점

- MVP 검증 이후
- 첫 PoC 고객이 본사용으로 전환할 때

## 3-3. 온프레미스 구축형 모델

대기업, 금융권, 공공기관에서 가장 큰 계약이 될 가능성이 있는 모델이다.

### 형태

- 고객사 내부 서버 또는 전용망에 설치
- 구축비 + 연간 유지보수비
- 필요 시 정책 커스터마이징 추가 과금

### 장점

- 대형 계약으로 이어질 수 있다.
- 보안 민감 조직에 적합하다.
- 고객이 가장 안심하기 쉬운 방식이다.

### 단점

- 구축과 지원 리소스가 많이 든다.
- 표준 제품이 아닌 SI 성격으로 흐를 위험이 있다.

### 권장 사용 시점

- 대기업 전략/재무/법무 조직
- 금융권
- 공공기관 및 공기업

## 3-4. 사용량 기반 SaaS 모델

장기적으로는 고려 가능하지만, 초기 주력 모델로는 후순위다.

### 형태

- 사용자 수 기반 과금
- 문서 수 또는 처리량 기반 과금
- API 호출량 또는 세션 수 기반 과금

### 장점

- 확장성이 좋다.
- 중소형 조직에 진입하기 쉽다.

### 단점

- 초기 보안 신뢰 형성 전에는 구매 설득력이 약할 수 있다.
- 공공/대기업 시장과는 결이 다를 수 있다.

## 4. 초기 권장 BM

현재 프로젝트 단계에서 가장 현실적인 BM 조합은 다음과 같다.

### 1단계

- 유상 PoC / 파일럿

### 2단계

- 연간 라이선스

### 3단계

- 온프레미스 구축형 + 유지보수 계약

즉, `PoC -> 라이선스 -> 구축형 확장` 흐름이 가장 자연스럽다.

## 5. 가격 정책 설계 기준

지금 단계에서는 숫자보다 가격 결정 기준이 더 중요하다.

### 가격을 정할 때 봐야 할 요소

- 사용자 수
- 부서 수
- 처리 문서량
- 정책 템플릿 수
- 외부 AI 연동 범위
- 온프레미스 여부
- 감사/로그 기능 범위
- 커스터마이징 수준

## 6. 고객 유형별 권장 가격 구조

## 6-1. 중견기업 / 빠른 도입 고객

### 적합 모델

- PoC
- 소규모 연간 라이선스

### 특징

- 빠른 도입 가능
- 단가보다 실용성을 본다
- 기능 검증 후 확장 가능성 확인

## 6-2. 대기업 / 금융권

### 적합 모델

- 유상 PoC
- 부서 단위 라이선스
- 온프레미스 구축형

### 특징

- 보안 검토가 길다
- 가격보다 승인 가능성과 운영 안정성이 중요하다
- 커스터마이징 요구 가능성이 높다

## 6-3. 공공기관 / 공기업

### 적합 모델

- 시범사업형 PoC
- 구축형 계약
- 연간 유지보수 계약

### 특징

- 정책 문서와 통제 구조가 중요하다
- 단계적 도입이 유리하다
- 제안서와 실증 근거가 중요하다

## 7. 가격을 설명하는 방식

이 제품은 "문서 치환기"로 보이면 단가가 낮아진다.

따라서 가격 설명도 기능 단위가 아니라 가치 단위로 해야 한다.

### 좋은 설명

- 외부 AI를 보안 정책 안에서 사용 가능하게 만드는 비용
- 로컬 LLM 인프라 투자와 운영 부담을 줄이는 비용
- 민감정보 노출 위험을 줄이면서 업무 생산성을 확보하는 비용

### 피해야 할 설명

- 단순 마스킹 툴
- 문자열 치환기
- 문서 필터

## 8. 권장 초기 가격 전략

초기에는 숫자를 고정하기보다 다음 정책이 적절하다.

- 첫 고객 1~2곳은 유상 PoC 중심
- 본계약은 연간 라이선스와 구축형 중 고객 특성에 따라 선택
- 커스터마이징은 별도 범위로 관리

## 9. 현재 결론

IPU AI 보안필터의 초기 BM은 대규모 SaaS 확장보다, `유상 PoC -> 연간 라이선스 -> 온프레미스 구축형` 순으로 확장하는 것이 가장 현실적이다.
