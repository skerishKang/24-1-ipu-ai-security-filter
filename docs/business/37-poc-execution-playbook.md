# IPU AI 보안필터 PoC Execution Playbook

## 목적

이 문서는 `IPU AI 보안필터`의 PoC를 실제로 시작했을 때 어떻게 준비하고, 어떻게 진행하고, 어떻게 결과를 정리할지에 대한 실행 기준을 정리한다.  
목표는 PoC가 기술 시연으로 끝나는 것이 아니라, 실제 도입 가능성을 판단할 수 있는 검증 과정이 되도록 만드는 것이다.

## 기본 원칙

- PoC는 작고 선명해야 한다.
- 기술 검증과 업무 검증을 같이 본다.
- 보안팀과 현업팀을 모두 포함해야 한다.
- 시작보다 종료 조건이 더 중요하다.

## PoC 시작 전 체크

### 고객 측 확인 항목

- 대상 부서가 정해졌는가
- 대상 문서 유형이 정해졌는가
- 보안 검토 담당자가 있는가
- 현업 사용 담당자가 있는가
- PoC 기간과 범위에 합의했는가

### 내부 확인 항목

- 데모 가능한 시나리오가 준비됐는가
- 고객 맞춤 예시 문구 또는 샘플이 있는가
- 성공 기준이 정리됐는가
- PoC 제안서와 설명 자료가 준비됐는가

## PoC 범위 설정 원칙

### 좋은 범위

- 부서 1곳
- 문서 유형 1~2개
- 텍스트 중심 또는 제한된 파일 입력
- 2~4주 기간

### 나쁜 범위

- 전사 공통 도입 전제
- 너무 많은 입력 형식
- 너무 많은 정책 요구
- 관리자 기능까지 한 번에 요구

## PoC 단계

## 1단계: 킥오프

목표:

- 문제 정의와 범위를 다시 맞춘다

해야 할 일:

- 고객 Pain Point 재확인
- 대상 문서 유형 확정
- 사용 방식 합의
- 성공 기준 합의
- 일정 확정

## 2단계: 초기 시연

목표:

- 고객이 실제 흐름을 이해하게 만든다

해야 할 일:

- 수동 모드 워크벤치 시연
- 원문 입력 -> 치환 -> 리포트 -> 복사용 프롬프트 흐름 설명
- 현재 가능한 것과 아직 안 되는 것 구분

## 3단계: 고객 맞춤 검증

목표:

- 고객 문서 흐름에서 실제 적합성을 본다

해야 할 일:

- 고객 샘플 문서 반영
- 민감정보 유형 확인
- 치환 결과 검토
- 사용성 피드백 수집

## 4단계: 리뷰 및 보완

목표:

- 문제점과 개선 포인트를 정리한다

해야 할 일:

- 현업 피드백 정리
- 보안팀 피드백 정리
- 품질/정책/입력 제한 이슈 정리

## 5단계: 종료 및 판단

목표:

- 다음 단계로 갈지 판단한다

해야 할 일:

- 성공 기준 달성 여부 확인
- 추가 PoC 필요 여부 판단
- 유상 전환 또는 확대 여부 논의

## PoC 중 꼭 기록할 것

- 어떤 문서 유형을 썼는지
- 어떤 민감정보 유형이 중요했는지
- 어떤 치환이 잘 됐고 안 됐는지
- 고객이 좋아한 점
- 고객이 불편해한 점
- 보안팀이 우려한 점

## 성공 기준 예시

### 기술 기준

- 민감정보 탐지 가능
- 치환 흐름이 안정적
- 복원 가능
- 기본 시연 반복 가능

### 업무 기준

- 현업이 실제 활용 가능성을 느낌
- 단순 마스킹 대비 더 실용적이라고 봄
- 제한적 범위에서라도 재사용 의향이 있음

### 보안 기준

- 보안팀이 통제 가능 구조로 이해함
- 외부 AI 직접 사용보다 나은 구조라고 판단함

## 실패 신호

- 고객이 문제를 자기 일로 느끼지 못함
- 범위가 너무 넓어 자꾸 흔들림
- 보안팀과 현업팀이 따로 움직임
- 성공 기준 없이 “일단 해보자”로 가고 있음
- 제품이 아니라 커스터마이징 프로젝트처럼 변함

## PoC 종료 후 산출물

- 짧은 결과 요약
- 성공 기준 달성 여부
- 개선 포인트
- 다음 단계 제안
- 필요 시 case study 초안

## 역할 분담

### 내부

- 데모 진행자
- 기술 검토 담당
- 문서 정리 담당
- 후속 제안 담당

### 고객 측

- 현업 실무자
- 보안 검토 담당
- 의사결정 또는 승인 담당

## PoC 후 다음 경로

### 경로 1: 유상 확대

- 부서 단위 pilot
- 반복 사용 검토

### 경로 2: 범위 재조정 후 재검증

- 입력 유형 축소
- 문서 유형 재선정
- 정책 요구 재정리

### 경로 3: 장기 후보 전환

- 당장 도입은 어렵지만 향후 다시 논의

## 운영 중 피해야 할 것

- 제품 범위보다 고객 요구를 무조건 다 받는 것
- 기술 시연만 하고 현업 검증을 빼먹는 것
- 보안팀과 현업팀 중 한쪽만 설득하는 것
- 중간 기록 없이 마지막에만 정리하는 것

## 결론

PoC의 목적은 기술 자랑이 아니라, `이 고객이 이 문제를 이 범위에서 실제로 풀 수 있는가`를 판단하는 것이다.  
IPU AI 보안필터의 PoC는 작고 선명하게 운영할수록, 다음 단계로 이어질 가능성이 높다.
