# IPU AI 보안필터 PoC Meeting Checklist

## 목적

이 문서는 고객사와 PoC 미팅을 할 때 반드시 확인해야 할 항목을 정리한다.  
목표는 `흥미로운 기술 소개`로 끝나는 미팅이 아니라, 실제 PoC 범위와 성공 기준을 합의하는 미팅으로 만드는 것이다.

## 기본 원칙

- 제품 설명보다 고객의 현재 제약을 먼저 확인한다.
- 처음부터 전사 도입 이야기를 하지 않는다.
- PoC는 좁고 선명해야 한다.
- 성공 기준은 정량/정성 두 축으로 잡는다.
- 보안팀과 현업팀의 관점을 같이 본다.

## 미팅 전 준비

### 1. 고객 기본 정보

- 산업군
- 조직 규모
- 주요 문서 업무 유형
- 생성형 AI 도입 여부
- 현재 사용 중인 모델 또는 플랫폼

### 2. 예상 Pain Point 정리

- 외부 AI 사용이 금지되어 있는가
- 비공식 사용이 있는가
- 로컬 LLM 구축을 검토 중인가
- 단순 마스킹이나 수작업 정리가 불편한가

### 3. 데모 준비

- 고객 산업군에 맞는 예시 문구 준비
- 텍스트 중심 수동 모드 데모 준비
- 치환 결과와 리포트가 바로 보이도록 준비

## 미팅 중 확인 질문

### 1. 현재 업무 방식

- 어떤 문서를 AI로 처리하고 싶은가
- 지금은 왜 못 하고 있는가
- 실제 현업에서 가장 답답한 지점은 무엇인가

### 2. 보안 제약

- 어떤 정보가 가장 민감한가
- 외부 반출 금지 기준은 무엇인가
- 보안팀이 가장 우려하는 포인트는 무엇인가
- 감사 또는 승인 절차가 있는가

### 3. 기술 환경

- 클라우드 AI 사용이 가능한가
- 온프레미스 요구가 있는가
- 내부망, 폐쇄망, 별도 보안망 조건이 있는가
- 기존 AI 포털이나 내부 시스템이 있는가

### 4. PoC 적합도

- 특정 부서 또는 특정 문서 유형으로 범위를 제한할 수 있는가
- 2~4주 단위 검증이 가능한가
- 기술 검토와 현업 검토를 함께 진행할 수 있는가

## PoC 범위 정의 체크리스트

### 1. 대상 부서

- 부서 1곳으로 시작 가능한가
- 실사용 담당자와 의사결정자가 분리되어 있는가

### 2. 입력 범위

- 텍스트만 먼저 할 것인가
- 파일 입력까지 포함할 것인가
- 음성 입력은 후순위로 둘 것인가

### 3. 민감정보 유형

- 회사명
- 인명
- 연락처
- 금액
- 내부 프로젝트명
- 기타 고객 고유 항목

### 4. 활용 목적

- 요약
- 문서 초안 작성
- 검토 보조
- 질의응답
- 보고서 정리

## 성공 기준 체크리스트

### 정량 기준

- 탐지된 민감정보 개수
- 치환 정확도
- 복원 정확도
- 처리 시간
- 사용자 재작업 감소 정도

### 정성 기준

- 사용자가 실제 업무에 쓸 수 있다고 느끼는가
- 보안팀이 통제 가능하다고 느끼는가
- 단순 마스킹 대비 품질 이점이 보이는가
- 로컬 LLM 대비 활용성이 높다고 느끼는가

## 미팅에서 꼭 합의할 항목

- PoC 목적
- 대상 부서
- 대상 문서 유형
- 제외 범위
- 일정
- 고객 측 담당자
- 검토 방식
- 종료 시 성공 판단 기준

## 피해야 할 상황

- 요구사항이 너무 넓은데 범위 합의가 없는 경우
- 보안팀 없이 현업만 참석한 경우
- 현업 없이 보안팀만 참석한 경우
- PoC 성공 기준 없이 “일단 해보자”로 가는 경우
- 고객이 처음부터 완성형 제품 수준을 기대하는 경우

## 권장 미팅 흐름

### 1. 현재 제약 확인

`지금 외부 AI를 어디까지 허용하고 계신가요?`

### 2. 문제 재정의

`막는 것이 목표인지, 안전하게 쓰게 하는 것이 목표인지`를 정리한다.

### 3. 데모 진행

- 원문
- 치환 결과
- 리포트
- 복사용 프롬프트

### 4. PoC 범위 제안

- 부서 1곳
- 텍스트 중심
- 제한된 문서 유형
- 2~4주

### 5. 성공 기준 합의

- 탐지/복원/사용성/보안 검토 기준을 명시한다.

## 미팅 후 정리 문서에 포함할 내용

- 고객이 겪는 핵심 제약
- PoC 필요성
- 대상 업무
- 예상 민감정보 유형
- 추천 PoC 범위
- 리스크
- 다음 액션

## 후속 액션 체크리스트

### 1. 고객 맞춤 예시 확보

- 샘플 문서
- 사용 시나리오

### 2. 내부 정리

- PoC 제안 초안 작성
- 기술 검토 포인트 정리
- 보안팀 예상 질문 정리

### 3. 다음 미팅 예약

- 현업 실무자
- 보안 담당자
- IT 또는 인프라 담당자

## 결론

좋은 PoC 미팅은 제품 설명을 많이 하는 자리가 아니라, `이 고객에게 어떤 좁고 선명한 검증을 할 것인가`를 정하는 자리다.  
IPU AI 보안필터는 특히 보안팀과 현업팀의 관점이 동시에 중요하므로, 범위와 성공 기준을 초기에 명확히 잡는 것이 가장 중요하다.
