# IPU AI 방화벽 One-Page Summary

## 1. 서비스 한 줄 정의

IPU AI 방화벽은 민감정보를 내부에서 보호·치환한 뒤, 생성형 AI 요청과 응답을 정책에 따라 통제할 수 있게 해주는 기업용 AI 방화벽이다.

## 2. 해결하려는 문제

기업과 공공기관은 생성형 AI의 높은 성능을 활용하고 싶지만, 내부 문서와 고객 정보를 외부 AI에 직접 입력하는 것에 큰 부담을 느낀다.

기존 선택지는 대체로 두 가지다.

- 외부 AI를 금지하고 생산성을 포기한다.
- 비싼 GPU 서버를 사서 로컬 LLM을 구축하지만 성능과 운영 부담을 감수한다.

IPU는 이 두 선택지 사이에서, `보호는 내부에서 하고 생성형 AI 사용은 정책으로 통제하는 구조`를 만든다.

## 3. 핵심 방식

1. 사용자가 텍스트, 문서, 음성 데이터를 입력한다.
2. 내부 보안 엔진이 민감정보를 탐지한다.
3. 민감정보를 세션별로 문맥 유지형 치환한다.
4. 외부 AI에는 치환된 데이터만 전달한다.
5. 응답은 내부에서 다시 복원한다.
6. 세션 종료 시 매핑은 폐기한다.

## 4. 왜 필요한가

이 서비스는 단순한 마스킹 도구가 아니다.

단순 [MASK] 방식은 문맥을 깨고, 외부 AI의 답변 품질을 떨어뜨릴 수 있다.

IPU는 `보호하면서도 사용할 수 있는 입력`을 만드는 것이 목표다.

즉, 외부 AI를 막는 솔루션이 아니라, 생성형 AI를 더 안전하게 허용하는 방화벽이다.

## 5. 주요 타깃 고객

초기 타깃은 일반 소비자가 아니라 보안 민감 조직이다.

- 대기업 법무, 전략, 재무, 특허 조직
- 금융권 내부 문서 자동화 조직
- 공공기관 및 공기업의 보고자료/정책 문서 조직
- 컨설팅, 회계, 특허 법인

이 고객들은 모두 `외부 AI 활용 니즈는 크지만, 민감정보 때문에 직접 사용이 어려운 조직`이라는 공통점을 가진다.

## 6. 고객이 얻는 가치

### 보안

- 민감정보 직접 외부 전송을 줄일 수 있다
- 세션 기반 휘발성 매핑으로 통제 구조를 설명할 수 있다

### 성능

- 로컬 LLM 성능 한계에 묶이지 않는다
- 외부 최고 성능 모델을 계속 활용할 수 있다

### 비용

- 전면 로컬 LLM 구축보다 가볍게 시작할 수 있다
- GPU 인프라 투자와 운영 부담을 낮출 수 있다

## 7. 초기 제품 방향

초기 MVP는 `수동 모드 보안 치환 워크벤치`다.

즉, 자동으로 외부 AI를 호출하는 것보다 먼저:

- 원문 입력
- 민감정보 탐지
- 치환 결과 확인
- 리포트 확인
- 외부 AI용 복사 프롬프트 제공

이 흐름을 확실히 만드는 것을 목표로 한다.

이 방식은 보안팀과 현업팀 모두에게 설명하기 쉽고, PoC에도 적합하다.

## 8. 장기 제품 방향

수동 모드 MVP 이후에는 다음 단계로 확장한다.

- 파일 업로드
- 음성 입력과 로컬 STT
- 자동 외부 AI 연동
- 응답 역치환 자동화
- 정책 관리
- 감사 로그
- 온프레미스 배포

## 9. 비즈니스 모델 방향

초기에는 대규모 SaaS보다 다음 흐름이 적합하다.

- 유상 PoC
- 연간 라이선스
- 온프레미스 구축형

즉, `파일럿 검증 -> 부서 도입 -> 조직 확장` 모델이 가장 현실적이다.

## 10. 제안서용 요약 문장

IPU AI 방화벽은 보안 때문에 생성형 AI 활용이 막힌 조직과, 성능 때문에 로컬 LLM만으로는 부족한 조직 사이를 연결하는 실용적인 AI 방화벽 계층이다.
