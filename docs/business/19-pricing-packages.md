# IPU AI 보안필터 Pricing Packages Draft

## 목적

이 문서는 `IPU AI 보안필터`의 초기 가격 구조와 판매 패키지 초안을 정리한다.  
목표는 지금 당장 확정 가격표를 만드는 것이 아니라, 고객 유형에 따라 어떤 제안 방식이 자연스러운지 정리하는 것이다.

## 기본 원칙

- 초기에는 단일 정가표보다 `PoC -> 유상 확장 -> 구축형` 흐름이 더 현실적이다.
- 고객 규모와 보안 요구 수준에 따라 가격 구조가 달라질 수 있다.
- SaaS형과 온프레미스형은 같은 가격 논리를 쓰지 않는다.
- 가격보다 먼저 `도입 리스크를 줄이는 제안 방식`이 중요하다.

## 권장 판매 구조

### 1단계: 유상 PoC

목적:

- 고객이 실제 문서 흐름에서 기술 적합성을 검증하도록 한다.
- 단순 관심 고객과 실제 의지가 있는 고객을 구분한다.

포함 예시:

- 대상 부서 1곳
- 텍스트 중심 수동 모드 또는 제한적 자동 모드
- 고객 맞춤 예시 반영
- 기본 결과 리포트

가격 방향:

- 고정형 프로젝트 비용
- 범위가 넓어질수록 별도 견적

### 2단계: 부서 단위 유상 도입

목적:

- 특정 팀 또는 특정 업무 흐름에서 반복 사용하도록 전환한다.

포함 예시:

- 사용자 수 제한
- 기본 정책 설정
- 정기 지원
- 리포트 또는 사용 지원

가격 방향:

- 월 구독형 또는 연간 계약형
- 사용자 수, 부서 수, 요청량에 따라 차등

### 3단계: 엔터프라이즈/온프레미스 구축

목적:

- 대기업, 금융권, 공공기관처럼 통제 요구가 높은 고객에게 맞춘다.

포함 예시:

- 온프레미스 배치
- 고객사 맞춤 정책
- 내부 시스템 연동
- 확장 지원
- 유지보수

가격 방향:

- 구축비 + 연간 라이선스 + 유지보수

## 패키지 초안

### Package A: Starter PoC

대상:

- 첫 검토 고객
- 제한된 부서
- 빠른 검증 목적

포함:

- 2~4주 PoC
- 텍스트 입력 중심
- 수동 모드 기반 검증
- 민감정보 탐지/치환/리포트 확인

권장 포지션:

- 가장 진입 장벽이 낮은 패키지
- 빠른 미팅 후 바로 제안 가능

### Package B: Team Pilot

대상:

- 특정 부서 내 반복 활용을 검토하는 고객

포함:

- 제한된 사용자 그룹
- 반복 테스트 환경
- 기본 정책 반영
- 제한적 자동 모드 검토 가능

권장 포지션:

- PoC 성공 후 첫 유상 전환용 패키지

### Package C: Enterprise Secure Deployment

대상:

- 대기업, 금융권, 공공기관
- 내부 통제와 감사 요구가 높은 조직

포함:

- 온프레미스 또는 내부 배치형
- 정책 커스터마이징
- 내부 시스템 연동 검토
- 운영 지원

권장 포지션:

- 고단가 구축형
- 전사 확산 전 단계 또는 본격 도입 단계

## 가격 산정 요소

### 1. 범위

- 대상 부서 수
- 사용자 수
- 문서 유형 수
- 입력 채널 수

### 2. 기술 난이도

- 기본 텍스트 입력인지
- 파일/음성 확장이 필요한지
- 고객 맞춤 민감정보 항목이 많은지
- 관리자 기능 요구가 있는지

### 3. 배치 방식

- 단순 시연형
- 제한된 SaaS형
- 온프레미스형

### 4. 지원 수준

- 기본 지원
- 정기 리뷰
- 운영 대응
- 커스터마이징

## 권장 가격 표현 방식

초기에는 숫자를 너무 단단하게 박기보다 구간형으로 말하는 것이 낫다.

예시:

- PoC: 범위에 따라 별도 제안
- Pilot: 사용자/부서 범위에 따라 월 또는 연 단위 협의
- Enterprise: 구축 범위와 보안 요구에 따라 별도 견적

이유:

- 아직 제품 기능이 고정되지 않았다.
- 고객마다 요구 수준 차이가 크다.
- 지나치게 이른 정가표는 협상력을 약화시킬 수 있다.

## 고객별 권장 제안 방식

### 대기업

- PoC -> 부서 파일럿 -> 전사 확장

### 금융권

- 유상 PoC -> 보안 검토 -> 구축형 또는 내부망형 확장

### 공공기관

- 시범사업 성격 PoC -> 제한적 운영 -> 별도 사업화 검토

### 전문 서비스 조직

- 비교적 빠른 PoC -> 구독형 또는 팀 단위 도입

## 초기 영업 시 피해야 할 것

- 처음부터 전사 가격표를 제시하는 것
- 기능 범위가 불명확한 상태에서 낮은 가격을 확정하는 것
- 모든 고객에게 동일한 패키지를 밀어붙이는 것
- 구축/운영/정책 지원을 가격에 반영하지 않는 것

## 권장 제안 흐름

1. 문제 공감 확보
2. 제한된 PoC 제안
3. 성공 기준 합의
4. PoC 유상 진행
5. 부서 단위 유상 확대 또는 구축형 논의

## 결론

IPU AI 보안필터의 초기 가격 전략은 `정가형 SaaS`보다 `유상 PoC와 맞춤형 확장`이 더 현실적이다.  
제품이 아직 발전 중인 단계에서는 가격을 낮게 고정하는 것보다, 고객의 보안 요구와 도입 범위에 맞춰 제안 구조를 설계하는 것이 중요하다.
