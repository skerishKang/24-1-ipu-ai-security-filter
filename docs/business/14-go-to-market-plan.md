# IPU AI 보안필터 Go-To-Market Plan

## 목적

이 문서는 `IPU AI 보안필터`를 실제 고객에게 어떻게 소개하고, 어떤 순서로 PoC를 만들고, 어떤 방식으로 유료 전환까지 연결할지를 정리한다.  
핵심 목표는 초기 시장을 넓게 잡기보다, 보안과 생산성의 충돌이 가장 심한 고객군부터 공략하는 것이다.

## 기본 방향

- 처음부터 모든 산업군을 노리지 않는다.
- `보안 때문에 외부 AI를 충분히 못 쓰는 조직`을 먼저 공략한다.
- `도입 이유가 분명하고, PoC가 가능한 조직`부터 시작한다.
- 대형 계약보다 `짧은 PoC -> 명확한 성과 -> 확장` 흐름을 우선한다.

## 핵심 메시지

IPU AI 보안필터의 영업 메시지는 단순하다.

- 외부 SOTA AI를 금지하지 말고 안전하게 쓰게 하자.
- 비싼 GPU 서버를 사서 낮은 성능의 로컬 LLM만 억지로 운영하지 말자.
- 민감정보는 내부에서 보호하고, 외부 AI는 최고 성능을 그대로 활용하자.

## 1차 타깃 고객

### 1. 대기업 법무/전략/재무 조직

- 외부 AI를 쓰고 싶지만 문서 유출이 두려운 조직
- 문서, 계약, 보고서, 요약, 분석 업무가 많음
- PoC 범위를 좁게 잡기 좋음

이유:

- 도입 효과가 비교적 빨리 보인다.
- 문서 기반 업무라 MVP 적용이 쉽다.
- `직원들이 이미 몰래 쓰고 있다`는 상황이 많아 Pain Point가 분명하다.

### 2. 금융권 AI 추진 부서 + 보안 부서

- 생성형 AI를 도입하고 싶지만 통제가 필요함
- 외부 모델 금지와 로컬 모델 운영 사이에서 고민하는 조직

이유:

- 예산 명분이 강하다.
- 보안팀과 현업팀의 충돌이 크기 때문에 해결책 수요가 있다.
- 도입 시 레퍼런스 효과가 매우 크다.

### 3. 공공기관/공기업 내부 문서 조직

- 외부 AI 활용 수요는 있는데 보안과 감사 이슈가 큼
- 제한된 업무 범위에서 시범 도입을 하기 좋음

이유:

- 정책, 감사, 승인 구조가 명확하다.
- `안전한 사용 조건`이 제시되면 시범사업 논리가 서기 쉽다.

## 후순위 고객

### 1. 컨설팅, 회계, 특허, 리서치 조직

- 문서 민감도가 높고 AI 활용 수요가 큰 조직
- 비교적 빠르게 PoC를 돌릴 수 있음

### 2. 중견기업 DX 조직

- 대기업보다 의사결정이 빠를 수 있음
- 다만 예산 규모와 보안 강도가 다소 약할 수 있음

## 피해야 할 초기 고객

### 1. 일반 소비자

- 보안 Pain Point보다 사용성 기대가 큼
- 지불 의사가 낮고 구매 단위가 작음

### 2. AI 활용 수요가 약한 조직

- 문제는 있지만 급하지 않음
- 도입 결정을 끌어내기 어렵다

### 3. 처음부터 전사 확산만 요구하는 조직

- MVP 단계에 비해 요구사항이 과도함
- 기능보다 보안 검토와 커스터마이징 부담이 커진다

## 판매 전략

### 1단계: 문제 공감 확보

고객에게 먼저 물어야 할 질문은 제품 기능이 아니라 현재의 막힘이다.

- 직원들이 외부 AI를 실제로 쓰고 있는가
- 공식적으로는 금지인데 비공식 사용이 있는가
- 로컬 LLM 구축을 검토 중이거나 이미 하고 있는가
- 보안팀과 현업팀 사이의 충돌이 있는가

### 2단계: 제품 소개

고객에게는 기술 구조보다 선택지 비교가 더 중요하다.

- 외부 AI 전면 금지
- 로컬 LLM 전면 구축
- 단순 마스킹
- IPU AI 보안필터

이 네 가지를 비교하면서 `보안과 성능 사이의 현실적 절충안`이라는 포지션을 강조한다.

### 3단계: 제한된 PoC 제안

처음부터 전사 도입을 말하지 않는다.

- 대상 부서 1곳
- 입력 유형 1~2개
- 2~4주
- 민감정보 탐지/치환/복원/사용성 검증

### 4단계: 성공 기준 합의

PoC는 시작보다 종료 기준이 중요하다.

- 탐지 정확도
- 복원 정확도
- 업무 적용 가능성
- 사용자 만족도
- 보안팀 검토 가능성

### 5단계: 유상 전환

PoC 후에는 다음 중 하나로 이어진다.

- 부서 단위 유상 확장
- 전사 보안 계층 도입 검토
- 온프레미스 구축형 제안

## 채널 전략

### 직접 영업

- 대표, 실무 책임자, 보안 담당자 대상 직접 제안
- 기존 네트워크 활용
- 보안/AI 도입 고민이 있는 조직에 바로 접근

### 레퍼런스 기반 확장

- 금융권 또는 대기업 한 곳의 사례가 매우 중요하다.
- 초기 1~2개 고객의 PoC 성공이 이후 영업 효율을 크게 좌우한다.

### 파트너 전략

- AI 도입 컨설팅 회사
- 보안 솔루션 유통사
- 클라우드/MSP 파트너

초기에는 직접 영업이 우선이고, 이후 파트너를 붙이는 것이 맞다.

## 초기 영업 제안 패키지

### 패키지 A: 사전 진단 미팅

- 현재 AI 사용 정책 점검
- 문서 유형과 위험 요소 파악
- PoC 적합도 판단

### 패키지 B: 제한적 PoC

- 부서 1곳
- 텍스트 입력 중심
- 수동 모드 또는 제한된 자동 모드
- 리포트와 개선 제안 제공

### 패키지 C: 확장 제안

- 부서 확대
- 관리자 기능
- 정책 설정
- 온프레미스 또는 내부 포털 연동

## 세일즈 우선순위

### 우선순위 1

- 대기업 문서 중심 부서
- 금융권 AI/보안 조직

### 우선순위 2

- 공공기관/공기업
- 컨설팅/회계/특허

### 우선순위 3

- 일반 중견기업
- 범용 SaaS형 확장

## KPI 초안

### 초기 단계

- PoC 미팅 수
- PoC 제안서 발송 수
- PoC 수주 수
- PoC 완료 수

### 전환 단계

- 유상 전환율
- 부서 확장 수
- 온프레미스 제안 수
- 레퍼런스 확보 수

## 리스크

### 리스크 1: 고객이 “그냥 로컬 LLM 쓰겠다”고 할 수 있음

대응:

- 성능, 운영 비용, 모델 품질 차이를 구체적으로 비교한다.

### 리스크 2: 고객이 “단순 마스킹이면 충분하다”고 볼 수 있음

대응:

- 문맥 손실과 업무 품질 저하를 PoC에서 직접 보여준다.

### 리스크 3: 고객이 처음부터 완벽한 보안을 요구할 수 있음

대응:

- 현실적인 통제 수준과 단계적 검증 접근을 제안한다.

## 권장 실행 순서

1. 대기업/금융권 대상 1차 후보군 정리
2. 사전 진단 미팅용 소개 자료 준비
3. PoC 제안 패키지 정리
4. 1~2개 초기 PoC 확보
5. 결과를 레퍼런스와 제안서로 재활용

## 결론

IPU AI 보안필터의 GTM은 대중 시장이 아니라 `보안 때문에 외부 AI를 충분히 못 쓰는 조직`을 먼저 공략하는 방식이어야 한다.  
초기에는 넓은 확산보다 강한 Pain Point가 있는 몇 개 고객을 잡고, 짧은 PoC로 문제 해결 가능성을 입증한 뒤 유상 확장으로 넘어가는 것이 가장 현실적이다.
