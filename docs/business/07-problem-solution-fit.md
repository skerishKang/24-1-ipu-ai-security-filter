# IPU AI 보안필터 Problem-Solution Fit

## 1. 문서 목적

이 문서는 `IPU AI 보안필터`가 어떤 문제를 해결하는지, 그리고 왜 기존 대안보다 더 설득력 있는지 정리하기 위한 문서다.

핵심 질문은 다음과 같다.

- 고객은 왜 이 문제를 실제로 아프게 느끼는가
- 기존 대안은 왜 충분하지 않은가
- IPU는 정확히 어떤 지점에서 가치를 제공하는가

## 2. 고객의 실제 문제

생성형 AI는 이미 업무 생산성을 크게 높일 수 있는 도구로 인식되고 있다.

하지만 대기업, 금융권, 공공기관에서는 다음 문제 때문에 실제 도입이 막히거나 제한된다.

### 문제 1. 외부 AI 사용은 성능이 좋지만 데이터 유출이 불안하다

- 계약 정보
- 고객 정보
- 재무 정보
- 내부 프로젝트명
- 전략 문서

이런 데이터가 그대로 외부 LLM API로 전달되는 것에 대한 불안이 크다.

### 문제 2. 로컬 LLM은 보안에 유리하지만 비용과 성능의 한계가 있다

- GPU 서버 구매 비용
- 운영 인력 필요
- 모델 관리와 업데이트 부담
- 외부 SOTA 대비 성능 열세 가능성

즉, 로컬 구축은 "안전하지만 무겁고 약한" 선택지가 될 수 있다.

### 문제 3. 보안팀과 현업팀이 원하는 것이 다르다

- 보안팀은 통제와 차단을 원한다.
- 현업팀은 성능과 편의성을 원한다.

이 둘을 동시에 만족시키는 구조가 없어서 실제 조직 도입이 지연된다.

## 3. 기존 대안과 한계

## 대안 A. 외부 AI 사용 금지

### 장점

- 가장 단순한 통제 방식
- 규정 설명이 쉽다

### 한계

- 현업 생산성 손실
- 실제로는 우회 사용 가능성 존재
- "금지"는 장기적으로 유지되기 어렵다

## 대안 B. 로컬 LLM 전면 구축

### 장점

- 데이터 통제 용이
- 내부망 운영 가능

### 한계

- 높은 인프라 비용
- 운영 부담
- 모델 품질과 속도에 대한 불만 가능성
- 모든 조직이 감당하기 어려움

## 대안 C. 단순 마스킹 / 레드랙션 도구

### 장점

- 구현이 비교적 쉽다
- 개인정보 직접 노출은 줄일 수 있다

### 한계

- 문맥이 깨진다
- 외부 모델 답변 품질이 낮아질 수 있다
- 고정 패턴은 쉽게 예측 가능하다
- 현업 만족도가 낮을 수 있다

## 4. IPU의 해결 방식

IPU는 위 대안의 중간이 아니라, 완전히 다른 접근을 택한다.

### 핵심 접근

1. 민감정보를 내부에서 탐지한다.
2. 단순 삭제가 아니라 문맥 유지형 치환을 수행한다.
3. 외부 AI에는 변환된 안전한 입력만 전달한다.
4. 응답은 내부에서 다시 복원한다.
5. 세션 종료 시 매핑은 폐기한다.

즉, `외부 SOTA 성능`과 `내부 데이터 보호`를 동시에 확보하려는 구조다.

## 5. 왜 이 방식이 더 설득력 있는가

## 5-1. 보안팀 입장

- 직접 원문이 외부로 나가는 구조를 줄일 수 있다
- 통제 구조를 설명하기 쉽다
- 세션 기반 운영과 정책 적용이 가능하다

## 5-2. 현업 입장

- GPT, Claude, Gemini 같은 고성능 모델을 계속 쓸 수 있다
- 단순 [MASK]보다 문맥 유지형이라 결과 품질을 기대할 수 있다
- 로컬 저성능 모델에 묶이지 않을 수 있다

## 5-3. 경영진 입장

- 전면적 로컬 LLM 구축보다 가볍게 시작할 수 있다
- PoC -> 본사용 -> 구축형 확장의 단계적 도입이 가능하다
- 보안과 생산성 사이의 균형점을 만든다

## 6. IPU가 가장 잘 맞는 상황

다음 조건이 동시에 있는 조직일수록 IPU와 잘 맞는다.

- 외부 AI를 쓰고 싶은 니즈가 강하다
- 민감정보 때문에 직접 사용이 어렵다
- 로컬 LLM 전면 구축은 부담스럽다
- 보안팀과 현업팀의 의견이 엇갈린다

즉, "AI를 쓰고 싶지만 보안 때문에 멈춰 있는 조직"이 핵심 고객이다.

## 7. 지금 단계에서의 제품 적합성

현재 IPU의 초기 MVP는 자동화보다 `수동 모드 보안 치환 워크벤치`에 가깝다.

이것이 오히려 맞는 이유는 다음과 같다.

- 먼저 치환 품질과 실무 유용성을 검증할 수 있다
- 보안팀이 검토 가능한 흐름을 제공할 수 있다
- 자동 연동 이전에 운영 신뢰를 쌓을 수 있다

즉, MVP 단계에서도 문제 해결 실험은 충분히 가능하다.

## 8. 한 줄 결론

IPU AI 보안필터는 "외부 AI를 막을 것인가, 내부 AI를 비싸게 구축할 것인가"라는 기존 선택지를 넘어, 내부 데이터는 보호하고 외부 최고 성능 AI는 계속 활용하게 해주는 실용적인 해결책이다.
