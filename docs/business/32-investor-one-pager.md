# IPU AI 보안필터 Investor One-Pager

## 한 줄 정의

IPU AI 보안필터는 민감정보를 내부에서 보호·치환한 뒤 외부 SOTA AI를 더 안전하게 활용할 수 있게 해주는 기업용 AI 보안 계층이다.

## 문제

생성형 AI의 업무 활용 수요는 이미 충분히 커졌지만, 대기업·금융권·공공기관은 보안과 감사 문제 때문에 외부 AI를 실제 업무에 폭넓게 적용하지 못하고 있다.

조직은 보통 세 가지 비효율적인 선택지 중 하나를 택한다.

- 외부 AI를 전면 금지한다
- 비싼 GPU 서버를 사서 로컬 LLM을 운영한다
- 수작업 마스킹이나 비공식 사용에 의존한다

이 세 방식은 모두 보안 또는 생산성 중 한쪽을 크게 희생시킨다.

## 해결책

IPU AI 보안필터는 `외부 AI를 막는 것`이 아니라 `더 안전하게 쓰게 만드는 것`에 초점을 둔다.

기본 흐름은 다음과 같다.

1. 사용자가 텍스트 또는 문서를 입력
2. 내부 엔진이 민감정보를 탐지
3. 민감정보를 내부에서 치환하고 세션 기반으로 관리
4. 외부 AI에는 치환된 안전한 입력만 전달
5. 필요 시 내부에서 응답을 다시 복원

즉, 기밀은 내부에 두고 외부 최고 성능 AI는 활용하게 해주는 중간 계층이다.

## 왜 지금인가

- 외부 SOTA 모델은 이미 업무에서 충분히 쓸 만큼 강해졌다
- 하지만 보안 정책과 감사 요구는 더 강해지고 있다
- `AI 성능`과 `보안 통제` 사이의 간극이 빠르게 커지고 있다

이 간극을 메우는 기업용 AI 보안 계층 수요는 점점 커질 가능성이 높다.

## 고객

초기 타깃 고객은 다음과 같다.

- 대기업 문서 중심 부서
- 금융권 AI/보안 조직
- 공공기관 및 공기업의 제한된 시범 부서
- 컨설팅, 회계, 특허, 법률 등 민감 문서가 많은 전문 서비스 조직

공통점은 `외부 AI 활용 수요는 높지만 보안 제약도 강하다`는 것이다.

## 차별점

- 외부 AI를 금지하지 않고 더 안전하게 쓰게 한다
- 로컬 LLM만 강요하지 않고 외부 최고 성능 모델 활용 가능성을 연다
- 단순 마스킹보다 실제 업무 적용 가능성을 중시한다
- 보안팀과 현업팀이 동시에 받아들일 수 있는 구조를 지향한다

## 비즈니스 모델

초기에는 다음 흐름이 현실적이다.

1. 유상 PoC
2. 부서 단위 Pilot
3. 연간 계약 또는 구축형 확장
4. 온프레미스/엔터프라이즈 배치

즉 범용 소비자 SaaS가 아니라, 기업용 보안 인프라의 확장 구조에 가깝다.

## 현재 진행 상태

현재는 수동 모드 중심 MVP를 구축 중이다.

- 수동 모드 워크벤치 프론트엔드
- manual-preview 백엔드 API
- 최소 탐지/치환/복원 엔진
- 세션 TTL 기반 저장소
- 기본 smoke test
- 텍스트 및 `.txt` 파일 기반 preview 흐름 확장

즉 방향과 기본 구조는 이미 정리된 상태이며, 다음은 고객 PoC에 맞춘 품질 고도화와 입력 확장이다.

## 향후 6~12개월 핵심

- 초기 고객 인터뷰 및 타깃 계정 접촉
- 제한된 PoC 확보
- 탐지/치환/복원 품질 개선
- 자동 모드와 파일 입력 확장
- 엔터프라이즈/온프레미스 요구 정리

## 리스크

- 기술적으로는 문맥 유지형 치환과 복원 안정성이 핵심 리스크다
- 사업적으로는 초기 고객 확보와 긴 엔터프라이즈 세일즈 사이클이 리스크다

대응 전략은 명확하다.

- 기술은 수동 모드와 좁은 PoC로 먼저 검증
- 사업은 강한 Pain Point가 있는 고객군에 집중

## 결론

IPU AI 보안필터는 생성형 AI 확산 과정에서 필연적으로 커지는 `외부 AI 활용 통제` 문제를 겨냥한다.  
이 제품은 AI 모델을 파는 것이 아니라, 조직이 외부 AI를 더 통제 가능하고 안전하게 활용하도록 만드는 기업용 AI 보안 계층을 지향한다.
