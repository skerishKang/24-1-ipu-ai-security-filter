# IPU AI 보안필터 Go / No-Go Checklist

## 목적

이 문서는 `IPU AI 보안필터`에서 특정 고객 기회, PoC, 기능 확장, 파트너 제안을 계속 밀고 갈지 아니면 멈추거나 보류할지 판단하기 위한 체크리스트다.  
목표는 감으로 결정하지 않고, 현재 단계에 맞는 기준으로 `계속할 것`과 `멈출 것`을 분리하는 것이다.

## 사용 원칙

- 모든 기회를 다 잡으려 하지 않는다.
- 지금 단계에 맞는지 먼저 본다.
- 제품 가치 검증과 거리가 먼 기회는 과감히 뒤로 미룬다.
- Go / No-Go는 감정이 아니라 기준으로 판단한다.

## 언제 이 문서를 쓰는가

- 특정 고객과 PoC를 시작할지 고민할 때
- 기능 확장을 바로 할지 미룰지 고민할 때
- 파트너 제안을 받을 때
- 커스터마이징 요구를 수용할지 판단할 때
- 한 달 또는 분기마다 우선순위를 재조정할 때

## 1. 고객 기회 Go / No-Go

### Go 신호

- 고객의 문제 강도가 분명하다
- 외부 AI 활용 수요가 실제로 있다
- 민감 문서가 실제 업무에 많이 쓰인다
- PoC 범위를 좁게 잡을 수 있다
- 현업과 보안팀 모두 참여할 수 있다
- 다음 미팅 또는 PoC로 이어질 가능성이 있다

### No-Go 신호

- 문제를 추상적으로만 말한다
- AI 활용 수요가 낮다
- 처음부터 전사 도입만 원한다
- PoC 범위를 좁히지 못한다
- 보안팀 또는 현업 중 한쪽만 있고 다른 쪽은 빠져 있다
- 계속 관심만 보이고 실제 행동이 없다

## 2. PoC 기회 Go / No-Go

### Go 신호

- 대상 부서가 정해져 있다
- 대상 문서 유형이 정해져 있다
- 기간과 성공 기준을 합의할 수 있다
- 고객이 샘플 문서 또는 예시를 줄 수 있다
- PoC 후 다음 단계 논의 가능성이 있다

### No-Go 신호

- “일단 해보자”만 있고 기준이 없다
- 범위가 넓고 계속 변한다
- 커스터마이징 요구가 과도하다
- 내부 승인 구조가 전혀 정리되지 않았다
- 유상 전환이나 후속 검토 가능성이 거의 없다

## 3. 기능 확장 Go / No-Go

### Go 신호

- 해당 기능이 PoC 성공 가능성을 높인다
- 데모 품질을 직접적으로 높인다
- 여러 고객에게 반복적으로 필요한 기능이다
- 현재 제품 포지션과 잘 맞는다

### No-Go 신호

- 기술적으로 흥미롭지만 고객 검증과 거리가 멀다
- 특정 한 고객의 예외적 요구에 가깝다
- 지금 단계에서 구현 비용이 너무 크다
- 설명만 복잡하게 만들고 핵심 가치는 더 흐려진다

## 4. 파트너 제안 Go / No-Go

### Go 신호

- 해당 파트너가 실제 고객 접점이 있다
- 보안 또는 AI 도입 맥락을 이해한다
- PoC나 구축형 제안을 같이 풀 수 있다
- IPU를 올바른 포지션으로 설명할 수 있다

### No-Go 신호

- 단순 소개만 가능하다
- 제품을 범용 AI 툴처럼만 이해한다
- 초기부터 과도한 커스터마이징 기대를 만든다
- 고객군이 너무 퍼져 있어 초점이 흐려진다

## 5. 내부 우선순위 Go / No-Go

### Go 신호

- 지금 해야 할 일과 다음에 해야 할 일이 구분된다
- 문서와 개발 방향이 정렬돼 있다
- 실제 고객 검증으로 이어질 작업이다

### No-Go 신호

- 문서만 늘어나고 행동이 없다
- 기능은 늘어나는데 고객 검증은 없다
- 메시지가 흔들리고 포지션이 넓어진다

## 빠른 판단 질문

아래 질문에 `예`가 많을수록 Go에 가깝다.

1. 이 기회가 초기 고객 검증에 직접 도움이 되는가
2. 이 기회가 PoC 가능성을 높이는가
3. 이 기회가 제품 포지션을 더 선명하게 해주는가
4. 이 기회를 받아도 범위가 과도하게 커지지 않는가
5. 이 기회가 향후 유상 전환 또는 레퍼런스로 이어질 수 있는가

## 권장 판단 방식

### Strong Go

- 문제 강도 높음
- 범위 명확함
- 다음 단계 가능성 높음

### Conditional Go

- 가능성은 있으나 조건이 있음
- 범위를 더 좁히거나, 담당자를 더 확보하거나, 성공 기준을 먼저 정해야 함

### No-Go

- 현재 단계와 맞지 않음
- 리소스 대비 의미가 약함
- 지금 잡으면 오히려 방향이 흐려짐

## 체크리스트 예시

### 예시 1: 특정 대기업 법무팀 PoC 요청

- 문제 강도: 높음
- 범위 명확성: 높음
- 보안팀 참여: 중간
- 유상 가능성: 중간
- 판단: Conditional Go

이유:

- 범위는 좋지만 보안팀 참여를 먼저 확보해야 한다

### 예시 2: 한 고객이 PDF, DOCX, 음성, 관리자 콘솔까지 한 번에 요구

- 문제 강도: 중간
- 범위 명확성: 낮음
- 구현 부담: 높음
- 판단: No-Go

이유:

- 현재 단계에 비해 너무 무겁고, PoC보다 구축 사업에 가깝다

## 기록 방식

판단 결과는 decision log 또는 monthly review에 짧게 남기는 것이 좋다.

- 무엇을 판단했는가
- Go / Conditional Go / No-Go 중 무엇인가
- 이유는 무엇인가
- 다음 액션은 무엇인가

## 결론

좋은 Go / No-Go 판단은 기회를 놓치지 않는 것이 아니라, `지금 잡아야 할 기회와 지금 놓아야 할 기회`를 구분하는 것이다.  
IPU AI 보안필터는 아직 초기 단계이므로, 범위를 넓히기보다 강한 문제와 선명한 PoC로 이어지는 기회에 집중하는 것이 중요하다.
