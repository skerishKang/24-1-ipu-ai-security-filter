# IPU AI 보안필터 Decision Log Template

## 목적

이 문서는 `IPU AI 보안필터`에서 중요한 제품, 기술, 사업 결정을 남기기 위한 템플릿이다.  
목표는 시간이 지난 뒤에도 `왜 이런 선택을 했는지`를 다시 이해할 수 있게 만드는 것이다.

## 사용 원칙

- 결정은 짧고 명확하게 적는다.
- 배경, 선택지, 최종 판단, 이유를 분리한다.
- 결과가 나중에 틀렸더라도 당시 기준을 남긴다.
- 작은 모든 선택이 아니라, 방향에 영향을 주는 결정만 기록한다.

## 기록이 필요한 결정 예시

- 제품 포지션 변경
- 고객군 우선순위 변경
- MVP 범위 확정
- 수동 모드/자동 모드 우선순위 판단
- 로컬 LLM/외부 SOTA 관련 구조 선택
- pricing/BM 구조 선택
- PoC 운영 방식 결정

## 템플릿

### 결정 제목

- 예: `초기 제품 포지션을 범용 AI 앱이 아니라 기업용 AI 보안 계층으로 고정`

### 결정 날짜

- YYYY-MM-DD

### 결정 상태

- Proposed
- Accepted
- Revisited
- Superseded

### 배경

- 어떤 상황에서 이 결정을 하게 되었는가
- 어떤 문제가 있었는가
- 어떤 혼선이 있었는가

### 선택지

- 선택지 A:
- 선택지 B:
- 선택지 C:

### 최종 결정

- 무엇을 선택했는가

### 이유

- 왜 그 선택이 현재 단계에 맞았는가
- 어떤 장점이 있었는가
- 어떤 리스크를 감수했는가

### 포기한 것

- 이 결정을 하면서 의도적으로 미룬 것
- 지금 하지 않기로 한 것

### 기대 효과

- 이 결정이 무엇을 더 명확하게 해주는가
- 제품/사업/개발 중 무엇에 도움이 되는가

### 재검토 조건

- 어떤 상황이 오면 이 결정을 다시 볼 것인가

예시:

- 실제 고객 반응이 예상과 다를 때
- PoC 실패가 반복될 때
- 고객군이 바뀔 때

## 짧은 예시 1

### 결정 제목

초기 MVP를 자동 모드보다 수동 모드 중심으로 간다

### 결정 날짜

2026-03-14

### 결정 상태

Accepted

### 배경

자동 모드는 외부 모델 래핑, 복원 안정성, 운영 이슈가 많아 초기 범위가 너무 커질 위험이 있었다.

### 선택지

- A: 자동 모드부터 구현
- B: 수동 모드 먼저 구현

### 최종 결정

수동 모드 먼저 구현

### 이유

문제 검증과 PoC 진입에는 수동 모드만으로도 충분하며, 기술 범위를 훨씬 더 좁게 유지할 수 있었다.

### 포기한 것

- 원클릭 자동 왕복 처리

### 기대 효과

- 빠른 데모 가능
- 제품 가치 검증 우선

### 재검토 조건

- 실제 고객이 자동 모드 없이는 PoC 진행이 어렵다고 반복적으로 말할 때

## 짧은 예시 2

### 결정 제목

기존 secure-bridge를 수정하지 않고 새 프로젝트를 분리한다

### 결정 날짜

2026-03-14

### 결정 상태

Accepted

### 배경

기존 프로젝트는 개념 검증용 구조였고, 새 방향은 웹 기반 제품 구조와 사업 문서 체계가 필요했다.

### 선택지

- A: 기존 프로젝트를 계속 수정
- B: 새 프로젝트를 생성

### 최종 결정

새 프로젝트 생성

### 이유

기존 구조 제약 없이 제품 기준으로 다시 설계하는 것이 장기적으로 더 명확했다.

### 포기한 것

- 빠른 재사용성 일부

### 기대 효과

- 문서/개발/사업 구조 일관성 확보

### 재검토 조건

- 기존 프로젝트에서 반드시 재사용해야 할 핵심 모듈이 매우 많다고 판단될 때

## 권장 운영 방식

- 큰 결정이 나올 때마다 문서 1개를 새로 만들거나, 월간 결정 로그에 누적한다.
- 분기 리뷰 때 기존 결정이 여전히 유효한지 다시 본다.
- roadmap, backlog, business 문서와 충돌이 생기면 decision log를 기준으로 왜 바뀌었는지 정리한다.

## 결론

좋은 decision log는 `무엇을 결정했는가`만 남기는 문서가 아니라, `왜 그 결정이 지금 단계에서 맞았는가`를 남기는 문서다.  
IPU AI 보안필터처럼 제품 방향과 사업 방향이 함께 움직이는 프로젝트에서는 특히 중요하다.
