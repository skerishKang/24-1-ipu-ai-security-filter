# IPU AI 보안필터 Pitch Deck Outline

## 목적

이 문서는 `IPU AI 보안필터`를 고객사, 파트너, 투자자, 팁스 운영사, 내부 의사결정자에게 설명할 때 사용할 발표자료의 기본 구조를 정리한다.  
핵심 목표는 제품의 필요성과 차별성을 짧은 시간 안에 전달하고, 왜 지금 이 문제를 풀어야 하는지 설득하는 것이다.

## 권장 분량

- 짧은 소개 미팅: 8~10장
- 고객 제안용: 10~12장
- 투자/운영사 설명용: 12~15장

## 권장 슬라이드 구조

### 1. 표지

- 서비스명: `IPU AI 보안필터`
- 브랜드명: `IPU (I'll Protect You)`
- 한 줄 설명:
  - 민감정보를 내부에서 보호·변환한 뒤 외부 SOTA AI를 안전하게 사용할 수 있게 해주는 기업용 AI 보안 서비스

### 2. 문제 정의

- 기업과 공공기관은 생성형 AI를 쓰고 싶지만, 기밀 유출이 두려워 사용을 제한한다.
- 그래서 조직은 세 가지 비효율 중 하나를 선택한다.
  - 외부 AI 전면 금지
  - 비싼 GPU 서버를 사서 로컬 모델 운영
  - 단순 마스킹 수준의 불완전한 우회 사용
- 결과적으로 생산성과 보안이 동시에 손해를 본다.

### 3. 기존 대안의 한계

- 외부 AI 금지:
  - 보안은 지키지만 업무 효율이 크게 떨어진다.
- 로컬 LLM 구축:
  - 보안은 유리하지만 성능, 운영 복잡도, 인프라 비용이 크다.
- 단순 마스킹:
  - 문맥이 깨져서 답변 품질이 낮아진다.

### 4. 해결책

- IPU AI 보안필터는 민감정보를 내부에서 탐지하고 치환한 뒤 외부 AI에 전달한다.
- 외부 AI는 치환된 안전한 문맥만 보고 응답한다.
- 내부 시스템이 응답을 다시 원래 맥락으로 복원한다.

### 5. 제품 동작 방식

- 사용자 입력
- 내부 보안 엔진 탐지
- 세션 기반 치환
- 외부 SOTA LLM 호출
- 응답 수신
- 내부 복원
- 사용자 전달

초기 MVP에서는 수동 모드도 함께 제공한다.

### 6. 핵심 차별점

- 단순 `[MASK]`가 아니라 문맥 유지형 치환을 지향한다.
- 외부 AI를 막는 제품이 아니라, 안전하게 쓰게 하는 제품이다.
- 로컬 LLM을 대체하는 것이 아니라, 외부 최고 성능 모델 사용을 가능하게 하는 보안 계층이다.
- 기업/공공의 온프레미스 요구에 대응 가능한 구조를 가진다.

### 7. 왜 지금 필요한가

- 기업 내부의 생성형 AI 수요는 이미 크다.
- 하지만 보안 정책과 감사 대응 때문에 실제 도입은 막혀 있다.
- 외부 AI를 허용하면서도 통제할 수 있는 중간 계층 수요가 커지고 있다.

### 8. 목표 고객

- 대기업 법무, 전략, 재무, 구매, 감사 조직
- 금융권 보안 및 AI 추진 부서
- 공공기관 및 공기업의 내부 문서 업무 조직
- 컨설팅, 회계, 특허, 리서치 조직

### 9. 도입 방식

- 1단계: 제한된 부서 대상 PoC
- 2단계: 사내 AI 포털 또는 업무 시스템 앞단 연동
- 3단계: 온프레미스 또는 전사 표준 보안 계층 확장

### 10. 비즈니스 모델

- 유상 PoC
- 연간 라이선스
- 온프레미스 구축형
- 유지보수 및 정책 커스터마이징 옵션

### 11. 경쟁 구도

- 경쟁 상대는 특정 스타트업 하나가 아니라 현재 고객의 선택지 전체다.
- 외부 AI 금지
- 로컬 LLM 직접 구축
- 단순 마스킹 솔루션
- 범용 AI 포털

IPU는 `보안`과 `성능 활용`의 균형점을 파는 포지션이다.

### 12. 현재 진행 상태

- 새 프로젝트 구조와 문서 체계 정리 완료
- 수동 모드 워크벤치 프론트엔드 골격 구현
- manual-preview 백엔드 API 스켈레톤 구현
- 엔진 인터페이스와 최소 치환/복원 구조 구현
- 다음 단계는 backend-engine 실제 통합과 시연 품질 고도화

### 13. PoC 제안

- 대상 문서 유형과 입력 범위를 제한해 2~4주 PoC 제안
- 측정 항목:
  - 민감정보 탐지율
  - 복원 정확도
  - 업무 적용 가능성
  - 사용자 만족도
  - 보안팀 수용 가능성

### 14. 장기 확장 방향

- 수동 모드에서 자동 모드로 확장
- 텍스트에서 파일/음성으로 확장
- 정책 기반 치환 전략 고도화
- 문맥 유지형 동적 alias 생성
- 관리자 콘솔, 감사 로그, 권한 정책 추가

### 15. 마무리 메시지

- 기업은 더 이상 `보안 때문에 AI를 포기`하거나 `보안을 위해 낮은 성능을 감수`할 필요가 없다.
- IPU AI 보안필터는 민감정보는 내부에 두고, 외부 최고 성능 AI는 안전하게 활용할 수 있게 해주는 현실적인 중간 해법이다.

## 청중별 강조 포인트

### 고객사 대상

- 도입 용이성
- 내부 보안 정책과의 정합성
- PoC 범위와 성공 기준

### 투자자/운영사 대상

- 문제의 시급성
- 엔터프라이즈 보안 인프라 포지션
- 확장 가능한 제품 구조

### 내부 의사결정용

- 제품 우선순위
- MVP 범위
- 사업성과 개발 방향의 정렬

## 발표 시 유의사항

- `암호화`라는 표현은 과도하게 쓰지 않는다.
- 대신 `민감정보 보호`, `내부 치환`, `문맥 유지형 보안 변환`, `AI 보안 계층` 같은 표현을 사용한다.
- “무조건 완벽한 보안”보다 “현실적인 도입 가능성과 통제 가능성”을 강조한다.
- 고객에게는 기술보다 도입 후 얻는 통제력과 생산성 회복을 먼저 설명한다.
