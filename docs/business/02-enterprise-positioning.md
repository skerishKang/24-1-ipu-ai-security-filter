# IPU AI 보안필터 엔터프라이즈 포지셔닝

## 1. 핵심 메시지

대기업은 생성형 AI를 쓰고 싶지만, 기밀 정보 유출 우려 때문에 실제로는 제한적으로만 사용한다.

IPU AI 보안필터는 이 문제를 다음 문장으로 해결하는 제품이다.

> 외부 SOTA AI를 막지 말고, 내부 데이터를 보호한 상태로 사용하게 하자.

## 2. 고객의 현재 선택지

대기업 입장에서 현재 선택지는 대체로 세 가지다.

### 선택지 A. 외부 AI 금지

- 보안은 강하다.
- 하지만 생산성이 낮다.
- 직원들은 우회 사용을 시도할 가능성이 높다.

### 선택지 B. 로컬 LLM 자체 구축

- 데이터 통제는 쉽다.
- 하지만 GPU 인프라 비용이 크다.
- 운영 인력과 유지보수 부담이 크다.
- 외부 SOTA 대비 성능이 아쉬울 수 있다.

### 선택지 C. 외부 AI 직접 사용

- 성능은 가장 좋다.
- 하지만 보안팀 승인과 리스크 통제가 어렵다.

IPU AI 보안필터는 선택지 B와 C 사이의 타협재가 아니라, 성능과 보안을 동시에 확보하려는 인프라 전략이다.

## 3. 포지셔닝 문장

### 내부용 설명

IPU AI 보안필터는 외부 AI 사용을 차단하는 솔루션이 아니라, 외부 AI를 안전하게 허용하기 위한 보안 필터다.

### 대외용 설명

IPU AI 보안필터는 민감한 업무 데이터를 내부에서 보호·변환한 뒤 외부 SOTA AI를 안전하게 사용할 수 있게 해주는 기업용 AI 보안 서비스다.

### 영업용 한 문장

비싼 GPU 서버를 추가로 사서 낮은 성능의 로컬 모델에 묶일 필요 없이, 내부 데이터는 보호하고 외부 최고 성능의 AI는 그대로 활용하게 해주는 솔루션이다.

## 4. 대기업 고객이 반응할 포인트

### 4-1. 보안팀

- 민감정보가 그대로 외부로 나가지 않는 구조
- 세션 단위 휘발성 매핑
- 온프레미스 또는 사내망 배치 가능성
- 향후 감사 로그, 정책 관리 확장 가능성

### 4-2. 현업 부서

- GPT, Claude, Gemini 같은 최고 성능 모델을 계속 쓸 수 있음
- 단순 마스킹보다 문맥 유지형 사용 가능
- 업무 효율 저하를 줄일 수 있음

### 4-3. IT/인프라 부서

- 전면적 로컬 LLM 인프라 투자 부담 완화
- 경량 내부 보안 엔진 중심으로 시작 가능
- 단계적 도입 가능

## 5. 왜 로컬 LLM 대체재가 아닌가

IPU AI 보안필터는 로컬 모델을 완전히 대체하려는 제품이 아니다.

오히려 역할 분리가 핵심이다.

- 경량 로컬 엔진: 탐지, 분류, 치환, 복원
- 외부 SOTA 모델: 요약, 분석, 추론, 생성

즉, "모든 것을 내부 모델로 해결"하려는 접근이 아니라 "내부에서 보호하고 외부에서 추론"하는 구조다.

## 6. 엔터프라이즈 세일즈 포인트

### 메시지 1

외부 AI를 막는 대신, 안전하게 허용하는 구조로 전환할 수 있다.

### 메시지 2

고성능 외부 AI의 생산성은 유지하면서, 민감정보의 직접 노출 위험은 줄일 수 있다.

### 메시지 3

전사적 로컬 LLM 인프라를 구축하기 전에, 훨씬 가벼운 구조로 AI 보안 레이어를 먼저 도입할 수 있다.

## 7. 초기 도입 대상 부서

대기업 내부에서도 모든 부서를 한 번에 공략할 필요는 없다.

가장 유력한 초기 부서는 다음과 같다.

- 법무
- 재무
- 전략
- M&A
- 특허
- 대외협력
- 고객 대응 문서 조직

이 부서들은 문서 민감도가 높고, 생성형 AI 활용 니즈도 분명하다.

## 8. 한 줄 포지셔닝

IPU AI 보안필터는 대기업이 고성능 외부 AI를 포기하지 않으면서도, 내부 보안 정책 안에서 안전하게 사용할 수 있게 해주는 AI 보안 필터 계층이다.
