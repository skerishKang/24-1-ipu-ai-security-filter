# IPU AI 보안필터 Quality Review Template

## 목적

이 문서는 `IPU AI 보안필터`의 결과 품질을 점검하기 위한 리뷰 템플릿이다.  
목표는 단순히 기능이 동작하는지를 넘어서, 실제 입력에 대해 탐지, 치환, 복원, 리포트가 PoC와 고객 검증에 쓸 만한 수준인지 평가하는 것이다.

## 사용 원칙

- 기능 동작과 결과 품질을 구분해서 본다.
- 정답률 하나만 보지 않는다.
- PoC 적합성 기준으로 품질을 본다.
- 기술적 품질과 설명 가능한 품질을 함께 본다.

## 리뷰 시점

이 문서는 아래 상황에서 사용한다.

- 엔진 품질 검증 세트 실행 후
- 고객 샘플 문서 테스트 후
- PoC 중간 점검 시
- 정책 분기나 입력 형식 확장 후

- 토큰 구조가 PoC/데모에 충분히 설명 가능한가

## 4. 현재 강점

- 무엇이 지금도 충분히 설득 가능한가
- 어떤 샘플에서는 이미 PoC 수준으로 보이는가

예시:

- 구조화된 manual-preview 흐름
- 텍스트와 `.txt` 파일 기준 반복 가능한 데모
- 기본 민감정보 탐지와 치환의 일관성

## 5. 현재 약점

- 어떤 입력에서 품질이 불안정한가
- 어떤 정책 분기가 아직 이름뿐인가
- 어떤 결과는 고객 앞에서 설명이 어려운가

예시:

- default 와 strict_token 의 실제 처리 차이가 약함
- 조직명/인명 탐지가 문맥에 따라 약할 수 있음
- 문맥 유지형 치환은 아직 초기 수준

## 8. 리뷰 예시 문장

- `기본 탐지와 치환 흐름은 PoC 데모 수준으로는 충분하지만, 정책별 실제 차이는 아직 약하다.`
- `텍스트와 .txt 입력은 반복 시연이 가능하지만, 고객 샘플 기준으로 조직명과 인명 탐지 품질을 더 봐야 한다.`
- `리포트 구조는 설명 가능하나, 보안팀 설득을 위해 strategy와 risk level 의미를 더 선명하게 보여줄 필요가 있다.`

## 결론

좋은 quality review는 “동작한다”를 확인하는 문서가 아니라, `이 결과가 실제 고객 앞에서 쓸 만한가`를 판단하는 문서다.  
IPU AI 보안필터는 초기 단계에서 기능 수보다 PoC 적합성이 더 중요하므로, 품질 리뷰도 그 기준으로 해야 한다.
