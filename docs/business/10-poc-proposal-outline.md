# IPU AI 보안필터 PoC 제안 개요

## 1. 문서 목적

이 문서는 `IPU AI 보안필터`를 대기업, 금융권, 공공기관에 파일럿 또는 PoC 형태로 제안할 때 사용할 수 있는 기본 틀을 정리한 문서다.

핵심은 "제품 설명"이 아니라 "어떤 범위로, 어떤 목표를 가지고, 어떤 결과를 확인할 것인가"를 제안 가능 형태로 만드는 것이다.

## 2. PoC 기본 방향

IPU의 초기 도입은 전사 구축보다 제한된 범위의 검증 프로젝트가 더 적합하다.

권장 방향은 다음과 같다.

- 특정 부서
- 특정 문서 유형
- 수동 모드 우선
- 짧은 기간
- 명확한 검증 지표

## 3. PoC 제안 대상

다음과 같은 조직이 초기 PoC 대상으로 적합하다.

- 대기업 법무팀
- 전략/재무 부서
- 금융권 문서 자동화 부서
- 공공기관 정책/보고자료 작성 조직
- 컨설팅/회계/특허 법인

## 4. PoC 목표 예시

PoC의 목적은 AI 답변 품질 자체를 완벽히 검증하는 것이 아니라, "민감정보 보호 상태에서도 외부 AI 활용이 실무적으로 가능한가"를 확인하는 것이다.

대표 목표는 다음과 같다.

- 민감정보가 포함된 원문을 보호형 치환으로 전환할 수 있는가
- 치환본이 외부 AI 활용에 충분한 문맥을 유지하는가
- 실무자가 결과를 검토 가능한 형태로 확인할 수 있는가
- 조직이 외부 AI 활용을 보안 정책 안에서 설명할 수 있는가

## 5. PoC 범위 예시

## 범위 A. 텍스트 중심 PoC

### 입력

- 계약서 문구
- 보고서 초안
- 고객 대응 문구
- 내부 회의 메모

### 기능

- 텍스트 입력
- 민감정보 탐지
- 치환 결과 생성
- 리포트 표시
- 복사용 외부 AI 프롬프트 제공

### 적합 대상

- 법무
- 전략
- 재무

## 범위 B. 파일 중심 PoC

### 입력

- PDF
- DOCX
- PPTX

### 기능

- 파일 업로드
- 텍스트 추출
- 민감정보 치환
- 요약용 프롬프트 생성

### 적합 대상

- 공공기관
- 금융권
- 컨설팅 조직

## 범위 C. 음성 중심 PoC

### 입력

- 회의 녹취
- 상담 녹취
- 인터뷰 음성

### 기능

- 로컬 STT
- 민감정보 치환
- 외부 AI 활용용 텍스트 출력

### 적합 대상

- 상담 조직
- 회의록 작성 조직

## 6. PoC 운영 방식

현재 단계에서 가장 적절한 운영 방식은 수동 모드 중심이다.

### 권장 방식

1. 고객이 샘플 데이터를 제공한다.
2. IPU가 수동 모드 워크벤치에서 보호형 치환을 수행한다.
3. 치환 결과와 리포트를 검토한다.
4. 외부 AI 활용 결과를 비교한다.
5. 실무 적합성과 확장 필요성을 평가한다.

이 방식은 보안팀과 현업팀 모두에게 설명하기 쉽다.

## 7. PoC 산출물 예시

PoC 종료 시 다음과 같은 산출물을 제공할 수 있다.

- 적용 대상 데이터 유형 정의서
- 탐지/치환 샘플 리포트
- 활용 가능 시나리오 정리
- 한계와 후속 개선 항목
- 자동 모드 확장 필요성 정리

## 8. PoC 성공 기준 예시

### 기능 기준

- 원문 입력 -> 치환 -> 리포트 -> 복사용 프롬프트 생성이 안정적으로 동작

### 보안 기준

- 민감정보 직접 노출 항목 감소
- 세션 기반 치환 흐름 설명 가능

### 업무 기준

- 현업 사용자가 외부 AI 활용 가능성을 체감
- 문맥 손실이 과도하지 않다고 평가

### 조직 기준

- 보안팀과 현업팀 모두 확장 가능성을 검토할 수 있는 수준 도달

## 9. PoC 이후 전환 시나리오

PoC가 성공하면 다음 전환 경로를 제안할 수 있다.

1. 동일 부서 확대 적용
2. 파일 입력 확대
3. 자동 모드 일부 도입
4. 조직 단위 라이선스 또는 구축형 논의

즉, PoC는 끝이 아니라 본사용 계약으로 가는 첫 단계다.

## 10. 제안서용 한 문장

IPU AI 보안필터 PoC는 민감정보를 직접 외부 AI에 노출하지 않고도, 고성능 생성형 AI를 실제 업무 흐름에 적용할 수 있는지를 검증하는 제한 범위 파일럿 프로젝트다.
