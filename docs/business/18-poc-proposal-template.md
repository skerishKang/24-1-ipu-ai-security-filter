# IPU AI 방화벽 PoC Proposal Template

## 문서 목적

이 문서는 고객사에 제안할 `IPU AI 방화벽 PoC`의 기본 템플릿이다.  
목표는 처음부터 큰 구축 사업으로 보이게 하는 것이 아니라, 제한된 범위에서 기술 가능성과 업무 적합성을 함께 검증하는 제안으로 만드는 것이다.

## 문서 사용 원칙

- 고객사 이름과 대상 부서에 맞게 수정한다.
- 처음부터 모든 기능을 넣지 않는다.
- PoC 범위는 좁고 측정 가능하게 유지한다.
- 기술 설명보다 고객의 현재 문제와 검증 목표를 먼저 쓴다.

## 1. 제안 개요

### 프로젝트명

`[고객사명] x IPU AI 방화벽 제한적 PoC 제안`

### 제안 목적

본 PoC는 고객사가 외부 SOTA AI를 활용할 때 발생하는 민감정보 노출 우려를 줄이면서, 실제 업무 문서에 대한 생성형 AI 활용 가능성을 검증하기 위한 것이다.

### 대상 기간

- 권장: 2주 ~ 4주

### 대상 범위

- 특정 부서 1곳
- 특정 문서 유형 1~2개
- 텍스트 중심 입력

## 2. 고객 배경

### 현재 상황

- 고객사는 생성형 AI 활용 수요가 있으나, 민감정보 반출과 보안 정책 때문에 외부 AI 활용에 제약이 있다.
- 이로 인해 실제 업무에서 AI 도입이 제한되거나, 비공식적이고 통제되지 않은 사용이 발생할 수 있다.

### 예상 문제

- 회사명, 인명, 연락처, 금액, 내부 프로젝트명 등 민감정보가 포함된 문서를 외부 AI에 그대로 넣기 어렵다.
- 단순 마스킹은 문맥 손실로 인해 품질 저하 가능성이 있다.
- 로컬 LLM 전면 구축은 비용과 운영 복잡도가 크다.

## 3. PoC 목표

본 PoC의 목표는 다음과 같다.

- 민감정보 탐지 및 치환 가능성 검증
- 외부 AI 활용 전 정책기반 방화벽 계층의 실효성 검증
- 수동 모드 또는 제한된 자동 모드 기준 업무 적용성 검증
- 보안팀과 현업팀이 모두 수용 가능한 운영 모델 검토

## 4. 제안 솔루션 개요

IPU AI 방화벽은 민감정보를 내부에서 탐지·치환한 뒤 생성형 AI 요청과 응답을 정책에 따라 통제하는 기업용 AI 방화벽이다.

기본 흐름:

1. 사용자가 텍스트 또는 문서를 입력
2. 내부 엔진이 민감정보 탐지
3. 세션 기반 치환 수행
4. 치환된 안전한 입력 생성
5. 외부 AI 활용
6. 필요 시 내부에서 역복원

PoC 초기 단계에서는 수동 모드 중심으로 진행할 수 있다.

## 5. PoC 범위

### 포함 범위

- 텍스트 중심 수동 모드 워크벤치
- 민감정보 탐지
- 세션 기반 치환
- 치환 결과 및 리포트 확인
- 복사용 프롬프트 생성

### 선택 범위

- 제한된 자동 모드 검토
- 특정 문서 유형 반영
- 고객 맞춤 민감정보 항목 추가

### 제외 범위

- 전사 시스템 연동
- 완성형 관리자 콘솔
- 대규모 사용자 운영
- 모든 문서/음성 처리 확장

## 6. 대상 업무 시나리오

예시:

- 회의 메모 요약
- 계약/제안서 검토 보조
- 내부 보고서 초안 정리
- 문서 기반 질의응답

고객 상황에 맞춰 실제 업무 시나리오 1~2개로 좁혀서 설정하는 것이 바람직하다.

## 7. 성공 기준

### 정량 기준

- 민감정보 탐지 수
- 치환 정확도
- 복원 정확도
- 처리 시간

### 정성 기준

- 현업 사용 가능성
- 단순 마스킹 대비 품질 우위
- 보안팀 수용 가능성
- 실제 도입 검토 의향

## 8. 추진 방식

### 1단계: 범위 확정

- 대상 부서 선정
- 문서 유형 선정
- 민감정보 유형 정의

### 2단계: 시연 및 초기 셋업

- 고객 맞춤 예시 데이터 반영
- 수동 모드 기반 시연
- 검증 시나리오 합의

### 3단계: PoC 수행

- 실제 또는 유사 문서 기준 테스트
- 결과 확인
- 개선 포인트 정리

### 4단계: 결과 리뷰

- 보안팀 리뷰
- 현업팀 리뷰
- 유상 확장 가능성 검토

## 9. 고객사 준비 사항

- 대상 부서 지정
- 샘플 문서 또는 예시 입력 제공
- 검토 담당자 지정
- 보안 검토 포인트 공유

## 10. IPU 제공 사항

- PoC 워크벤치 환경
- 시연 및 기술 설명
- 민감정보 치환 흐름 제공
- 결과 리포트 및 개선 제안

## 11. 예상 일정

예시:

- 1주차: 범위 정의 및 시연
- 2주차: 샘플 데이터 적용 및 테스트
- 3주차: 피드백 반영
- 4주차: 결과 정리 및 확장 논의

## 12. PoC 이후 확장 방향

PoC 결과가 긍정적일 경우 다음 단계로 확장할 수 있다.

- 특정 부서 유상 도입
- 입력 유형 확대
- 정책 기반 치환 고도화
- 온프레미스 또는 내부 포털 연동 검토
- 관리자 및 감사 기능 확장

## 13. 제안 메시지

IPU AI 방화벽의 PoC는 `외부 AI를 쓸 것인가 말 것인가`를 논의하는 단계가 아니라, `외부 AI를 더 통제 가능하고 안전하게 활용할 수 있는가`를 검증하는 단계다.  
초기에는 좁고 선명한 범위에서 시작해 실제 도입 가능성을 판단하는 것이 가장 현실적이다.

## 14. 마무리 문구 예시

`귀사의 보안 정책과 업무 활용 수요를 함께 고려할 때, 본 PoC는 외부 SOTA AI 활용 가능성을 현실적으로 검증할 수 있는 최소 범위의 시범사업으로 설계되었습니다. 우선 제한된 부서와 문서 유형을 대상으로 실효성을 확인한 뒤, 향후 확장 여부를 함께 논의드리고자 합니다.`
