# 00. Master Roadmap

## 1. 문서 목적

이 문서는 `IPU AI Firewall` 프로젝트의 장기 작업 기준 문서다.

목표는 다음 세 가지를 동시에 정렬하는 것이다.

- 제품 방향
- 개발 우선순위
- 사업 문서와 기술 문서의 역할 분리

즉, 개별 문서나 개별 구현 작업이 흩어지지 않도록 상위 로드맵 역할을 한다.

## 2. 프로젝트 한 줄 정의

IPU AI Firewall은 민감정보를 내부에서 탐지, 치환, 복원한 뒤 생성형 AI 요청과 응답을 정책에 따라 통제하는 기업용 AI 방화벽이다.

## 3. 현재 프로젝트 상태

현재는 다음 단계까지 진행된 상태다.

- 새 프로젝트 구조 생성 완료
- 문서 우선 MVP 골격 확정
- 제품 개요, 시스템 아키텍처, MVP 범위, 백로그 문서 생성
- 사업 포지셔닝 문서 생성
- 실제 구현은 스켈레톤 진입 직전 단계

현재 단계의 핵심 의미는 "무엇을 만들 것인가"가 고정됐다는 점이다.

## 4. 전체 단계 개요

프로젝트는 크게 4단계로 나눈다.

### Phase 0. Foundation

문서, 구조, 역할, 경계, MVP 정의를 고정하는 단계

### Phase 1. Manual Workbench MVP

수동 모드 중심 보안 치환 워크벤치를 만드는 단계

### Phase 2. Secure Workflow Expansion

파일, 음성, 정책, 세션 관리 등 실무 입력 경로를 확장하는 단계

### Phase 3. Enterprise Productization

자동 모드, 외부 모델 연동, 관리자 기능, 배포 전략까지 확장하는 단계

## 5. 각 단계의 목표

## Phase 0. Foundation

### 목표

- 프로젝트의 제품 방향을 문서로 고정
- 프론트엔드, 백엔드, 엔진의 책임 분리
- 수동 모드를 MVP의 기준으로 확정

### 완료 기준

- `README.md`, `AGENTS.md`, `docs/*.md`가 일관된 방향을 가짐
- 구조와 문서가 서로 충돌하지 않음
- 다음 구현자가 어떤 순서로 들어가야 하는지 명확함

## Phase 1. Manual Workbench MVP

### 목표

사용자가 텍스트를 입력하면 안전한 치환본을 만들고 검토할 수 있는 웹 기반 워크벤치를 완성한다.

### 포함 기능

- 텍스트 입력
- 민감정보 탐지
- 치환 결과 생성
- 탐지 리포트 표시
- 외부 AI용 복사 프롬프트 생성
- 세션 단위 매핑 관리

### 완료 기준

- 브라우저에서 수동 모드 워크플로우가 동작함
- 원문, 치환본, 리포트, 복사본을 확인할 수 있음
- 엔진과 API 계약이 실제로 연결됨

## Phase 2. Secure Workflow Expansion

### 목표

수동 모드 MVP를 실무 입력 경로 중심으로 확장한다.

### 포함 기능

- 파일 업로드
- 파일 파서 연결
- 음성 업로드
- 로컬 STT 연결 가능 구조
- 정책 프리셋
- 세션 만료 및 복원 규칙 정교화

### 완료 기준

- 텍스트 외 입력도 수동 워크벤치로 처리 가능
- 정책에 따라 탐지/치환 결과가 달라질 수 있음
- 엔터프라이즈 PoC 데모가 가능한 수준의 입력 다양성이 확보됨

## Phase 3. Enterprise Productization

### 목표

실제 기업 도입을 염두에 둔 운영 기능과 자동 모드를 붙인다.

### 포함 기능

- 외부 모델 자동 연동
- 응답 역치환 자동화
- 감사 로그 범위 정의
- 관리자 정책 관리
- 조직 단위 배포 전략
- 온프레미스/사내 서버 운영 전략

### 완료 기준

- 자동 모드가 수동 모드 위에서 안정적으로 동작함
- 운영자와 보안 담당자가 제품을 설명할 수 있음
- 제안서/PoC/파일럿 수준 문서와 기능이 정렬됨

## 7. 지금 시점의 최우선 개발 순서

현재 기준으로 가장 적절한 개발 순서는 다음과 같다.

1. 수동 모드 워크벤치 화면 흐름 정의
2. `manual-preview` API 계약 초안 작성
3. 엔진 `detect / replace / restore / report` 인터페이스 스켈레톤 구현
4. 프론트엔드와 백엔드 mock 연동
5. 엔진 placeholder를 실제 로직으로 대체

## 8. 지금 시점의 최우선 사업 문서 순서

현재 기준으로 가장 적절한 사업 문서 순서는 다음과 같다.

1. 사업 개요
2. 대기업 포지셔닝
3. 공공 포지셔닝
4. 세일즈 메시지
5. BM 및 과금 전략
6. 고객 페르소나
7. 도입 시나리오

## 9. 의사결정 포인트

앞으로 프로젝트에서 중요한 결정은 다음 순서로 정리한다.

### 제품 결정

- 수동 모드만으로도 고객 가치가 충분한가
- 자동 모드는 언제 붙일 것인가
- 입력 타입 우선순위는 텍스트/파일/음성 중 무엇인가

### 기술 결정

- 경량 로컬 모델 도입 시점
- 규칙 기반 탐지와 모델 기반 탐지의 경계
- 세션 저장 범위와 폐기 정책

### 사업 결정

- 첫 고객군은 대기업/금융/공공 중 어디인가
- PoC형 판매로 시작할지, 연간 라이선스로 갈지
- 온프레미스가 기본인지, 관리형 배포가 기본인지

## 10. 작업 운영 원칙

- 큰 방향은 문서에서 먼저 정리한다.
- 구현은 문서를 따르되, 구현 중 문서와 충돌하면 먼저 충돌 지점을 명시한다.
- 수동 모드를 먼저 완성하고 자동 모드는 확장 구조로만 설계한다.
- 기존 `24-secure-bridge`는 구조 복제가 아니라 개념 참고용으로만 사용한다.
- 사업 문서와 개발 문서는 같은 목표를 보되, 서로 역할이 다르다는 점을 유지한다.

## 11. 다음 체크포인트

다음 체크포인트는 아래 세 가지 중 어느 수준까지 왔는지로 판단한다.

### Checkpoint A

- 프론트엔드 워크벤치 mock 화면 완성

### Checkpoint B

- 백엔드 `manual-preview` API 스켈레톤 완성

### Checkpoint C

- 엔진 인터페이스와 기본 테스트 스켈레톤 완성

이 세 가지가 완료되면 Phase 1의 실질 구현이 시작된 것으로 본다.

## 12. 한 줄 결론

IPU AI Firewall은 지금 문서 기반 방향 고정 단계를 통과했으며, 다음 단계는 수동 모드 보안 치환 워크벤치를 실제로 구현하는 것이다. 사업 문서와 개발 문서는 병렬로 움직이되, 모두 이 로드맵을 기준으로 정렬한다.
