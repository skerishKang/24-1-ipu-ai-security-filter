# 40. Reentry Intent And Next Plan

## 목적

이 문서는 재부팅이나 세션 종료 후 다시 `24-1-ipu-ai-security-filter` 작업을 시작할 때, 지금까지의 의도와 다음 우선순위를 빠르게 복구하기 위한 재진입 문서다.

## 프로젝트의 현재 의도

IPU의 핵심 의도는 단순하다.

- 텍스트
- 문서
- 음성

이 세 입력을 같은 `manual-preview` 보안 필터 경로로 태워서, 민감정보를 먼저 치환한 뒤 외부 AI를 더 안전하게 쓰게 하는 것이다.

즉 음성을 계속 만진 이유는 "음성도 텍스트처럼 보안 치환하고 싶다"는 제품 확장 의도 때문이다.  
나중에는 영상도 같은 방식으로 붙일 수 있다.

- 영상 업로드
- 영상에서 오디오 추출
- STT
- 민감정보 치환

이 흐름으로 확장하는 것이 자연스럽다.

## 지금까지 한 일의 의미

최근까지의 작업은 크게 두 덩어리다.

### 1. 제품 확장으로서 의미 있는 작업

- audio upload 경로 추가
- 로컬 Whisper 연결
- real whisper smoke / real audio API smoke 확인
- 일반인/전문가 모드 음성 업로드 노출

이 부분은 "음성도 같은 보안 경로에 넣는다"는 제품 방향과 맞는다.

### 2. 우선순위를 넘어서 깊게 들어간 작업

- 오디오 샘플 메타 체계
- 샘플 관찰 노트 포맷
- sample-002 / sample-003 TODO
- 소스 조사 메모
- registry 정리

이 부분은 나중에 분명 쓸 수 있지만, 현재 시점에서는 제품 가치보다 운영 문서를 너무 길게 판 작업이었다.

즉 최근의 과한 점은:

- 오디오 확장 자체가 아니라
- 오디오 샘플 운영 문서를 지나치게 세분화한 것이다

## 현재 판단

지금부터는 오디오 문서 체계를 더 늘리는 것보다, 실제 제품 데모와 사용자 체감 가치 쪽으로 우선순위를 되돌리는 것이 맞다.

## 지금 당장 유지할 것

- 텍스트 / 문서 / 음성 경로는 계속 유지
- 오디오는 입력 채널 확장으로서 남김
- 다만 회의 녹음 / 다화자 / diarization 문서는 여기서 잠시 멈춤

## 지금 당장 멈출 것

아래 작업은 실제 새 자산이 생기기 전까지 더 파지 않는다.

- sample-002 / sample-003 문서 세분화
- audio sample registry 추가 확장
- diarization 후보 문서 추가 확장
- 샘플 메타 체계 추가 세분화

## 다음 우선순위

### Main mission

IPU manual-preview를 "문서가 많은 프로토타입"이 아니라 "바로 시연 가능한 보안 제품 데모"로 정리한다.

### Current quest

현재 실제로 보여줄 사용자 흐름 1개를 고정하고, 그 흐름 기준으로 화면/문구/실행 경로를 정리한다.

## 추천 데모 플로우

우선순위는 아래 순서가 맞다.

1. 텍스트 붙여넣기 -> 민감정보 치환 -> 복사용 프롬프트 확인
2. 문서 업로드 -> 치환 -> restore 확인
3. 음성 업로드 -> STT -> 치환 확인

즉 음성은 유지하되, 제품의 1번 데모가 되어서는 안 된다.  
첫 시연은 텍스트 또는 문서 경로가 더 안정적이다.

## 재시작 시 바로 할 일

1. 현재 데모에서 보여줄 핵심 플로우 1개 결정
2. 그 플로우 기준으로 프론트 문구와 상태 메시지 정리
3. 필요하면 backend/frontend 실행 경로 다시 점검
4. 데모 시나리오 문서 1개 작성
