# OpenAI 열림 프로그램 아이템 적합성 정리

## 한 줄 판단

`24-1-ipu-ai-security-filter`는 OpenAI `열림` 프로그램에 **상당히 잘 맞는 편**이다.  
다만 아이템을 "`AI 보안 필터/오케스트레이션 계층`"으로 더 선명하게 정리해서 써야 한다.

## 왜 적합한가

이번 공고와 OpenAI `열림` 자료에서 특히 맞물리는 지점은 아래다.

- AI가 부가 기능이 아니라 제품의 핵심 구조다
- 최신 OpenAI 모델 활용 가능성이 높다
- agent / workflow / tool calling 구조와 잘 맞는다
- 외부 AI 사용 전 보안 필터링, 치환, 복원, 가드레일, 로그 같은 운영 계층이 분명하다
- 고객 데이터와 외부 생성형 AI를 안전하게 연결하는 문제를 푼다는 점에서 협업 명분이 강하다

특히 사업계획서 특화 항목에서 강조되는 아래 방향과 잘 맞는다.

- 최신 OpenAI 모델 활용
- 과업 특화 AI agent / workflow
- 고객 데이터 및 업무 시스템 연결
- 운영 보안, 권한, 감사, 가드레일
- 평가 체계와 모니터링, 비용/성능 최적화

즉 `IPU AI Security Filter`는 단순한 챗봇이 아니라,  
`기업 데이터가 외부 생성형 AI로 나가기 전에 통제하는 제품 계층`으로 설명할 수 있다.

## 아이템을 어떻게 써야 하나

지금 기준으로는 아래 표현이 제일 맞다.

> 기업 업무 데이터와 문서를 외부 생성형 AI에 안전하게 연결하기 위한  
> AI 보안 필터 및 실행 오케스트레이션 계층

조금 더 풀면 이렇다.

- 텍스트, 문서, 음성 입력을 받는다
- 민감정보를 탐지한다
- 외부 AI에 보내기 전 안전한 형태로 치환한다
- 필요 시 복원 가능한 세션 구조를 유지한다
- 정책별 보안 수준을 다르게 적용한다
- 이후 agent/workflow/업무 시스템 연결까지 확장 가능한 구조를 가진다

즉 핵심 가치는 "`AI를 더 똑똑하게 만든다`"가 아니라  
"`기업이 AI를 실제 업무에 안전하게 쓸 수 있게 만든다`"에 있다.

## 이 아이템의 강점

### 1. OpenAI 협업 명분이 분명함

이 제품은 OpenAI 모델을 그냥 호출하는 수준이 아니라,  
어떤 데이터를 어떤 정책으로 어떤 흐름에서 안전하게 태울지까지 포함한다.  
그래서 OpenAI 측의 기술 가이드, 모범 아키텍처, agent/workflow 관련 지원과 연결 명분이 있다.

### 2. 기업용 문제를 푼다는 점이 분명함

기업은 생성형 AI를 쓰고 싶어도 아래가 항상 문제다.

- 개인정보
- 계약/재무/고객정보
- 내부 문서 외부 유출 우려
- 권한/로그/감사 문제

이 제품은 바로 그 지점을 푼다.

### 3. 기술 과시보다 제품 구조로 보이기 좋음

manual-preview, policy preset, restore, 파일 입력, 음성 입력, session store 같은 축은  
“기술 데모”가 아니라 “운영 가능한 제품 구조”로 쓸 수 있다.

## 약한 점과 보완 포인트

### 1. 너무 넓게 쓰면 흐려짐

지금 구조상 텍스트, 문서, 음성, 나중엔 영상까지 확장 가능하지만,  
지원서에서 이걸 다 전면에 내세우면 오히려 산만해질 수 있다.

초기 서술은 이렇게 좁히는 게 낫다.

- 1차: 문서/텍스트 기반 기업 AI 보안 필터
- 2차: 음성까지 확장 가능한 멀티모달 보안 계층

### 2. “보안”만 말하면 추상적으로 들릴 수 있음

`보안 강화` 같은 말만 쓰면 흔한 문구로 보일 수 있다.  
반드시 아래처럼 구체 기능으로 내려와야 한다.

- 민감정보 탐지
- 치환
- 정책별 처리
- 복원
- 로그/감사 메타
- 외부 AI 호출 전 가드레일

### 3. 고객과 사용 장면이 더 선명해야 함

누가 언제 왜 쓰는지 더 좁혀 써야 한다.

예시:

- 기업 실무자가 계약서/제안서/내부 보고서를 AI에 넣기 전에 안전 처리
- 상담/운영 음성을 전사 후 안전하게 AI 분석에 연결
- 기업 내부 문서를 agent workflow에 연결하기 전 전처리 계층으로 사용

## 지원서에서 추천하는 아이템 프레이밍

## 추천 제목 톤

- 기업용 생성형 AI 보안 필터링 및 실행 계층
- 외부 생성형 AI 연계를 위한 민감정보 보호 오케스트레이션
- 기업 업무데이터의 안전한 AI 활용을 위한 보안 프록시 계층

이 중에서 가장 무난한 건 아래다.

> 기업 업무데이터의 안전한 AI 활용을 위한 보안 필터 및 오케스트레이션 계층

## 추천 문제정의

기업은 생성형 AI의 생산성 효과를 원하지만,  
문서/텍스트/음성에 포함된 민감정보 때문에 실제 현업 연결이 막혀 있다.  
현재는 사용 금지 또는 수작업 삭제에 의존해 비효율이 크다.

## 추천 해결방식

사용자가 입력한 텍스트, 문서, 음성을 제품이 먼저 받아  
민감정보를 탐지하고 정책에 맞게 치환한 뒤 외부 AI와 연동한다.  
필요 시 복원 가능 구조와 로그/운영 메타를 함께 제공해  
기업이 생성형 AI를 업무에 안전하게 연결할 수 있게 한다.

## OpenAI 협업 가능성 섹션에서 강조할 것

지원서의 `OpenAI 서비스 및 아이템 협업 가능성`에는 아래를 강하게 쓰는 게 좋다.

- OpenAI 최신 모델을 실제 업무 문서/질의/요약/분석 workflow에 연결하려면 안전한 입력 계층이 필요하다
- IPU는 그 입력 계층과 정책 제어 계층을 담당한다
- OpenAI의 agent/workflow best practice, tool orchestration, evaluation 체계와 직접 연결 가능하다
- 향후 문서형 workflow, 음성형 workflow, 기업 내부 시스템 연계형 workflow로 확장 가능하다

즉 `우리는 OpenAI를 쓰는 스타트업`이 아니라  
`OpenAI를 기업 업무에 안전하게 도입시키는 제품`으로 보여야 한다.

## KPI/성공계획에서 잡기 좋은 축

- AI 활용 전처리 시간 단축
- 민감정보 노출 위험 감소
- 문서/텍스트 처리량 증가
- 정책별 탐지 정확도/운영 안정성
- 실제 기업 PoC 또는 파일럿 수
- OpenAI 기반 업무 workflow 적용 사례 수

## 협업 로드맵에서 쓰기 좋은 흐름

### 1단계

문서/텍스트 중심의 AI 보안 필터 MVP 고도화

### 2단계

OpenAI 모델 연동 기반 문서 요약/질의/분석 workflow 연결

### 3단계

음성 입력과 업무 시스템 연결을 포함한 멀티모달 보안 계층 확장

## 피해야 할 서술

아래처럼 쓰면 약해질 가능성이 크다.

- 범용 AI 비서
- 이것저것 다 되는 AI 플랫폼
- 막연한 개인정보 보호 솔루션
- 기술 나열만 많은 연구 프로젝트

대신 아래처럼 써야 한다.

- 기업이 외부 AI를 안전하게 쓰게 만드는 제품
- 실제 문서/텍스트/음성 입력을 AI workflow에 연결하는 실행 계층
- OpenAI 협업 시 가치가 더 커지는 제품 구조

## 현재 최종 판단

이 아이템은 OpenAI `열림` 프로그램에 **적합한 편이 아니라, 오히려 강한 축에 가깝다**.  
핵심은 아이템을 "`AI 보안 필터 + 오케스트레이션 계층`"으로 선명하게 정리하고,  
너무 넓게 퍼뜨리지 말고 `기업 업무 데이터의 안전한 AI 활용`이라는 한 줄 문제에 집중하는 것이다.
